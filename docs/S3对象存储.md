# GlacierTDB S3 对象存储手册

> 兼容 AWS S3 的对象存储模块（可选）：AWS Signature **V4** 标准签名鉴权，一个 bucket 一张表
> 存于系统库 `glacier_s3.db`，独立 HTTP(S) 监听器（默认 `0.0.0.0:9000`，不进 3309 复用）。
> 面向工控机 / 物联网边缘环境的本地对象存储，替代 MinIO / 简单文件服务器——
> 备份 = 拷贝数据目录，迁移 = 拷贝文件。
>
> 配置详见 [配置说明.md](配置说明.md) §2.10；管理 SQL 详见 [系统SQL.md](系统SQL.md) §1.10。

## 1. 开启与寻址

```yaml
s3:
  enable: true            # 可选模块开关（默认 false）
  region: "*"             # '*' / 空 = 客户端任意 region 或不传；具体值 = 签名 scope 必须一致
  endpoints:
    - listen: 0.0.0.0:9000          # HTTP
      server_names: [s3.example.com] # virtual-host 后缀（客户端访问的主机名）
    - listen: 0.0.0.0:9001          # HTTPS 独立端口
      tls: true
      cert_file: /data/certs/wildcard.pem
      key_file: /data/certs/wildcard.key
      server_names: [s3.example.com]
```

**两种寻址方式**（同一监听器同时接受）：

| 方式 | 形式 | 说明 |
| --- | --- | --- |
| path-style | `http(s)://{endpoint}/{bucket}/{key}` | 兼容保留，任何客户端可用 |
| virtual-host | `http(s)://{bucket}[.{region}].{endpoint}` | `server_names` 配置的主机名为后缀；点号桶名优先按整段匹配。**v1.3.12 兜底**：`server_names` 未涵盖的域名，首段命中已建桶即自动按 virtual-host 处理（域名部署免配置）；未命中维持 path-style |
| 自定义域名 | `http(s)://{自定义域名}/{key}` | 每 bucket 可绑域名 + 独立证书（§7） |

> **virtual-host 兜底语义（v1.3.12 修复）**：此前未配置 `server_names` 的域名访问
> 一律按 path-style 处理——`bucket.s3.example.com` 的 `GET /` 会被误当 ListBuckets、
> `PUT /obj` 被误当建桶。现在对非 IP 多段域名把首段当桶名探一次库：命中已建桶 →
> vhost 语义（`GET /` 列该桶对象）；未命中 → path-style（端点裸域名 `GET /` 仍正确
> 列桶）。IP 访问与已配置 `server_names` 的环境行为不变。
>
> **region 说明（v1.3.12）**：region 不再按桶存储（`s3_buckets.region` 列弃用，
> 存量值启动时自动清空）——签名校验与 `GET ?location` 恒走全局 `s3.region`；
> `CREATE BUCKET ... REGION` 子句仅为兼容旧脚本保留（值被忽略）。

桶命名遵循 S3 规则：3-63 位小写字母 / 数字 / 点 / 连字符，字母数字开头结尾。

## 2. 认证：AK/SK 与 AWS Signature V4

- **AK 32 位（前缀 `AS`）、SK 48 位（前缀 `SK`）**；一个用户可配多组密钥；
- **SK 明文仅签发 / 轮换时返回一次**，此后不可再取。落表存 SHA-256 指纹 + AES-256-GCM 密文
  （SigV4 校验要用 SK 派生签名密钥，故密文可还原、不存纯哈希；加密主密钥
  `<db_dir>/glacier_s3.key` 首次启动自动生成，权限 0600，请随数据目录一并备份）；
- 签名算法为 **AWS Signature V4 标准**（`AWS4-HMAC-SHA256`）：表头鉴权（`Authorization` 头）与
  **预签名 URL**（`X-Amz-Signature` 查询参数）均支持；`aws-chunked` 流式负载自动解码——覆盖
  旧式 `STREAMING-AWS4-HMAC-SHA256-PAYLOAD` 与**新版 botocore / AWS CLI 默认的 CRC32 校验和
  trailer 编码**（`STREAMING-UNSIGNED-PAYLOAD-TRAILER`、`STREAMING-AWS4-HMAC-SHA256-PAYLOAD-TRAILER`
  等 `STREAMING-*` 声明，按 `x-amz-decoded-content-length` 校验净荷长度），boto3 默认配置
  （`request_checksum_calculation` 无需调整为 `when_required`）即可直连 HTTPS 端点；
  负载哈希与实际字节不符报 `BadDigest`；
- 时钟偏差容忍 ±15 分钟；SDK 兼容：boto3 / aws-cli / MinIO Client / 各语言 AWS SDK
  （endpoint 指向本服务、region 与配置一致或配置 `*`）。

密钥管理（管理面，仅超级用户）：

```sql
USE GlacierTDB;
CREATE S3 KEY FOR 'glacier';        -- 返回 AK + SK（SK 仅此一次可见）
RENEW S3 KEY 'ASXXXXXXXX...';       -- 轮换 SK（旧 SK 立即失效）
DISABLE S3 KEY 'AS...';  ENABLE S3 KEY 'AS...';
DROP S3 KEY 'AS...';                -- 吊销删除
SHOW S3 KEYS [FOR 'glacier'];       -- 不含 SK 明文
```

## 3. 存储模型

系统库 `<db_dir>/glacier_s3.db`（与 `glacier_auth.db` 同样不对客户端暴露、禁 CREATE/DROP）：

| 表 | 内容 |
| --- | --- |
| `s3_buckets` | 桶注册表：属主 / 版本开关 / 对象锁开关 / 回调 / 限速覆盖 / 存储字节 / 对象数（region 列 v1.3.12 起弃用，恒空） |
| `s3_keys` | AK/SK：指纹 + 密文 + 状态（active/disabled/revoked）+ 请求策略 |
| `s3_usage` | 计费记账（用户 × 桶）：GET/PUT/LIST/DELETE 计数、上传/下载字节、存储占用、对象数 |
| `s3_lifecycle` | 生命周期规则：桶 + 前缀 + 天数 |
| `s3_domains` | bucket 自定义域名 + 独立证书 |
| `s3_policies` | 桶级请求策略 JSON |
| `obj_<桶>` | 每桶一张对象表：key / version_id / is_latest / delete_marker / size / etag / 内容类型与缓存头 / `x-amz-meta-*` 元数据 / 内联内容 / 对象锁 |
| `chk_<桶>` | 分块表：超过 `inline_max_kb`（默认 64KB）的对象按 `chunk_kb`（默认 8MB）分块存储 |

- **桶从属用户**（`bucket → owner`）：命名空间隔离——密钥属主只能访问自己名下的桶，
  超级用户全放行；`CREATE BUCKET ... OWNER '<u>'` 指定属主（默认 `s3.default_owner`）；
- 对象 ETag = 内容 MD5；单对象上限 `s3.max_object_mb`（默认 512MB）。

## 4. 对象操作（S3 API）

| 操作 | 请求 | 说明 |
| --- | --- | --- |
| 列桶 | `GET /` | ListBuckets（仅自己名下，超管全量） |
| 建桶 / 删桶 / HEAD | `PUT/DELETE/HEAD /{bucket}` | `DELETE ?force` 或 `X-Glacier-Force: 1` 强删非空桶 |
| 列对象 | `GET /{bucket}?list-type=2` | ListObjects V2：prefix / delimiter / max-keys / continuation-token / start-after；V1（marker）同样支持 |
| 列版本 | `GET /{bucket}?versions` | ListObjectVersions（含删除标记） |
| 上传 | `PUT /{bucket}/{key}` | 支持 `x-amz-meta-*`、`x-amz-copy-source` 复制、`aws-chunked` |
| 下载 | `GET /{bucket}/{key}[?versionId=]` | 限速下发（§5）、图片加工（§6） |
| HEAD | `HEAD /{bucket}/{key}` | 元数据 |
| 删除 | `DELETE /{bucket}/{key}[?versionId=]` | 版本桶打删除标记；`?versionId=` 硬删该版本 |
| 版本配置 | `GET/PUT /{bucket}?versioning` | `PUT` 体 `<VersioningConfiguration><Status>Enabled</Status></VersioningConfiguration>` |
| 位置 | `GET /{bucket}?location` | 返回全局 `s3.region`（v1.3.12：桶不再单独存 region；`*`/空 → 空串） |

分片上传（multipart：InitiateMultipartUpload / UploadPart / Complete）**已支持**，见 §4.1。

### 4.1 分片上传（multipart）

| 操作 | 请求 | 说明 |
| --- | --- | --- |
| 发起 | `POST /{bucket}/{key}?uploads` | InitiateMultipartUpload → XML 返回 `UploadId`（对象属性 Content-Type / `x-amz-meta-*` 此时给定） |
| 上传分片 | `PUT /{bucket}/{key}?partNumber=N&uploadId=…` | 响应 `ETag` = 该分片内容 MD5；同序号重传覆盖（最后一次为准）；支持 `aws-chunked` |
| 完成 | `POST /{bucket}/{key}?uploadId=…` | body = `<CompleteMultipartUpload><Part><PartNumber>N</PartNumber><ETag>"…"</ETag></Part>…</CompleteMultipartUpload>`；响应 ETag = `MD5(各 part MD5 顺序拼接)-N`（S3 复合 ETag 语义），随后对象按普通 GET/HEAD 可读 |
| 中止 | `DELETE /{bucket}/{key}?uploadId=…` | 204，清理分片与会话 |
| 列分片 | `GET /{bucket}/{key}?uploadId=…` | ListParts（升序） |
| 列会话 | `GET /{bucket}?uploads` | ListMultipartUploads（`prefix` 过滤 key） |

用法与边界：

```python
# boto3 / aws-cli 标准用法即可（multipart 自动走以上六个 API）
mpu = s3.create_multipart_upload(Bucket="demo", Key="big.bin", ContentType="application/octet-stream")
s3.upload_part(Bucket="demo", Key="big.bin", UploadId=mpu["UploadId"], PartNumber=1, Body=chunk1)
s3.complete_multipart_upload(Bucket="demo", Key="big.bin", UploadId=mpu["UploadId"],
    MultipartUpload={"Parts": [{"PartNumber": 1, "ETag": etag1}, ...]})   # 或直接 aws s3 cp（自动分片）
```

- **校验**：partNumber 1..10000；Complete 所列 part 必须齐全（缺片 `InvalidPart`）、序号严格递增
  （`InvalidPartOrder`）、ETag 与已上传分片一致；合并后大小受 `max_object_mb` 约束（单分片同样受约束）；
  未知/过期 uploadId → `NoSuchUpload`；
- **存储**：分片暂存桶分块表，Complete 按序合并走对象两段式写入（inline/chunk），成功后分片即清理；
- **管理面**：`SHOW S3 UPLOADS [<bucket>]` / `SELECT * FROM s3_uploads`（分片数 / 字节聚合）；
  记账沿用 `s3_usage`（UploadPart 记 PUT + bytes_in、Abort 记 DELETE）；Complete / 覆盖写触发上传回调（§8）；
- **拷贝分片**：`PUT ?partNumber=N` 携带 `x-amz-copy-source: /srcBucket/srcKey[?versionId=V]`
  （可选 `x-amz-copy-source-range: bytes=first-last`）服务端拷贝分片，应答 `CopyPartResult` XML，
  与直传分片可混合 Complete；
- **未完成上传自动回收**：`s3.abort_incomplete_days`（默认 7 天，0=关闭）周期任务自动
  Abort 超龄会话；手动回收仍可用 `DELETE ?uploadId=` 或管理面 `DROP BUCKET <name> FORCE`。

## 5. 限速（下载）与并发

```yaml
s3:
  limits:
    per_conn_bps: 0        # 单连接下载 bytes/s（0 = 不限）
    per_user_bps: 0        # 单用户总带宽（多连接合并聚合，多线程下载合计不超过此值）
    per_user_conns: 0      # 单用户并发连接上限（超限 503 SlowDown）
  bucket_limits:
    backup: { per_conn_bps: 1048576 }   # 按桶覆盖（非 0 字段生效）
```

- 管理面行级热改（重启失效回配置 / 桶行存续）：
  `ALTER BUCKET <b> LIMIT CONN_BPS = 1048576` / `USER_BPS` / `USER_CONNS`；
- 优先级：全局 `limits` < `bucket_limits` 配置覆盖 < 桶行热改；
- 令牌桶突发额度 = 1 秒速率，保证多线程合并后总带宽不超限。

## 6. 请求策略条件（防滥用）

密钥级 / 桶级策略 JSON（AND 语义，全部满足才放行；不满足 403 `AccessDenied`）：

```json
{
  "ua": "app-*/*",
  "referer": "https://example.com/*",
  "ip": ["192.168.0.0/16", "10.1.2.3", "172.16.%"],
  "headers": {"x-app": "iot", "x-env": "prod"},
  "methods": ["GET", "PUT"]
}
```

- `ua` / `referer` / `headers` 值支持通配（`*` 任意串、`?` 单字符）；
- `ip` 支持精确 IP / CIDR / 前缀 `%`，任一命中即过；
- `methods` 大小写不敏感；
- 管理面：`SET S3 POLICY KEY '<ak>' '<json>'` / `SET S3 POLICY BUCKET '<b>' '<json>'` /
  `CLEAR S3 POLICY KEY|BUCKET ...` / `SHOW S3 POLICIES`。

## 7. TLS 证书（SNI · 自定义域名 · 热加载）

- **每 endpoint 一张泛域名证书**（`cert_file` / `key_file`，SNI 兜底）；
- **每 bucket 自定义域名 + 独立证书**（SAN 映射到 bucket）：

```sql
ALTER BUCKET demo ADD DOMAIN 'img.example.com' ISSUE;                 -- 自签发接入即用（365 天）
ALTER BUCKET demo ADD DOMAIN 'img.example.com' CERT FILE '/path/c.pem' KEY FILE '/path/k.pem';
ALTER BUCKET demo DROP DOMAIN 'img.example.com';
SHOW S3 DOMAINS;
```

- 自签发证书落 `<db_dir>/certs/<域名>.pem|.key`；生产建议上传正式证书（或在前面放反代终止 TLS）；
- **热加载**：证书文件替换（mtime 变化）即生效，无需重启；域名增删通过管理面即时刷新。

## 8. 上传回调

**三级配置（v1.3.12）**——请求级 > 桶级 > 全局，secret 同链覆盖：

| 级别 | 配置方式 | 生效范围 |
| --- | --- | --- |
| 请求级 | `PUT / CompleteMultipartUpload` 请求头 `x-glacier-callback-url: <url>`（可选 `x-glacier-callback-secret: <s>`） | 仅该次上传 |
| 桶级 | `SET S3 CALLBACK <bucket> URL '<url>' [SECRET '<s>']`（`CLEAR S3 CALLBACK <bucket>` 清除） | 该桶全部上传 |
| 全局 | `s3.callback_url` / `s3.callback_secret` 配置项 | 未配置高级别的上传 |

```sql
SET S3 CALLBACK demo URL 'http://app:8080/s3hook' SECRET 'cbsecret';
CLEAR S3 CALLBACK demo;
```

```bash
# 请求级：单次 PUT 指定回调（优先于桶级/全局 URL）
curl -H "x-glacier-callback-url: http://app:8080/once" \
     -H "x-glacier-callback-secret: once-secret" \
     -T file.jpg http://s3:9000/demo/file.jpg
```

对象写入完成后 POST JSON（`event=object_created`，含 bucket / key / version_id / size / etag /
content_type / replaced / ts），带 `X-Glacier-Signature: sha256=<HMAC-SHA256(body, secret)>` 头，
失败按 0/1s/5s/15s 退避重试；secret 按同链取第一个非空值。

## 9. 图片预处理

GET 查询参数（可组合；不加工则纯透传）：

| 参数 | 说明 |
| --- | --- |
| `x-gimg-crop=左,上,宽,高` | 裁剪 |
| `x-gimg-resize=宽,高` | 双线性缩放（某维 0 = 按比例） |
| `x-gimg-format=jpeg\|png` | 格式转换（解码 JPEG/PNG/GIF，编码 JPEG/PNG） |
| `x-gimg-quality=1..100` | JPEG 质量（默认 85） |
| `x-gimg=base64` | 输出 base64 文本；`x-gimg=base64dataurl` 带 `data:<mime>;base64,` 前缀 |

**base64 图片直传**：`PUT /{bucket}/{key}?x-gimg=base64`——body 为 base64 文本（兼容 data URL
与换行），解码后二进制落盘，之后按普通对象读写。

## 10. 多版本 · 对象锁（WORM）· 生命周期

```sql
ALTER BUCKET demo VERSIONING ON;      -- 版本链：每次 PUT 新版本，DELETE 打删除标记
ALTER BUCKET demo OBJECT_LOCK ON;     -- 对象锁开关（标记用）
S3 RETAIN demo/report.pdf UNTIL '2027-01-01' COMPLIANCE;   -- 不可旁路
S3 RETAIN demo/report.pdf UNTIL '2027-01-01' GOVERNANCE;   -- 可用 x-amz-bypass-governance-retention: true 旁路
S3 LEGAL_HOLD demo/report.pdf ON;
SET S3 LIFECYCLE demo PREFIX 'tmp/' DAYS 7;   -- 到期删除全部版本（后台周期扫描）
SHOW S3 LIFECYCLE;  SHOW S3 OBJECTS demo LIKE 'tmp/' LIMIT 50;
```

- 保护期内（retain_until 未到 / legal hold 开）删除、覆盖写一律 403；
- 生命周期扫描周期 `s3.lifecycle_interval_sec`（默认 3600 秒）；
- `GET /{bucket}/{key}?versionId=...` 取历史版本，`?versions` 列版本链。

## 11. 计费统计与导出

- 记账维度：**用户 × 桶**（桶属主为计费实体）；GET/PUT/LIST/DELETE 请求数、上传/下载字节、
  存储占用、对象数；
- SQL 直查：`SELECT * FROM s3_usage WHERE owner='glacier'` / `SHOW S3 USAGE [FOR '<u>']`；
- 导出接口（计费系统拉取）：
  - `EXPORT S3 USAGE [FOR '<u>'] [TO 'usage.csv']` → 落 `<db_dir>/exports/`；
  - HTTP `GET /_glacier/s3/usage?format=json|csv[&owner=<u>]`（SigV4 鉴权；超管可拉全量，
    普通用户仅自己）。

## 12. 客户端示例（boto3）

```python
import boto3
s3 = boto3.client("s3", endpoint_url="http://10.25.250.30:9000",
                  aws_access_key_id="AS......", aws_secret_access_key="SK......",
                  region_name="us-east-1")     # region 配置为 '*' 时任意
s3.create_bucket(Bucket="demo")
s3.put_object(Bucket="demo", Key="a.txt", Body=b"hello", ContentType="text/plain")

    print(o["Key"], o["Size"])
```

> 分片上传（大文件自动走 multipart）首版不承诺，请改用单次 PUT（≤ `max_object_mb`）。

## 13. 已知边界

- multipart 支持 UploadPartCopy 拷贝分片与未完成会话自动回收（§4.1）；单分片受 `max_object_mb` 约束（`-1` 解除）；
- `aws-chunked` 逐块签名仅消费不校验（种子签名已校验，HTTPS 下可接受）；
- 不承诺纠删码 / 跨机副本——单机单写者模型；
- 自签发证书为信任自签（浏览器会告警），生产请上传正式证书或前置反向代理。

## 分片上传增强

- **UploadPartCopy（拷贝分片）**：`PUT /{bucket}/{key}?partNumber=N&uploadId=X` 携带
  `x-amz-copy-source: /srcBucket/srcKey[?versionId=V]`（可选
  `x-amz-copy-source-range: bytes=first-last`，闭区间）——从源对象服务端拷贝指定字节段
  作为分片，免客户端重传；应答 `CopyPartResult` XML（ETag/LastModified 在 body，区别于
  直传分片的 header ETag）；拷贝分片与直传分片可混合 Complete；源不存在 `NoSuchKey`、
  越界 Range `InvalidArgument`(400)；
- **未完成上传自动回收**：`s3.abort_incomplete_days`（默认 7，`0` = 关闭）——生命周期
  周期任务（`lifecycle_interval_sec`，默认 1 小时）自动 Abort 超龄未完成会话并回收分片
  存储（`SHOW SERVER CONFIG` 可见 `s3.abort_incomplete_days`）；此前需手动 `Abort` 或
  `DROP BUCKET FORCE`；
- **单对象上限解除**：`s3.max_object_mb` 设负值（如 `-1`）= 不限制——对象与分片大小
  校验全部放行（分块存储为流式 chunk，本不受内存约束）；默认 512 不变。

## OpenCV 风格图片预处理

`x-gimg-ops` 操作管道：`|` 分隔多步，每步 `name(args)`，命名对齐 OpenCV——

| 操作 | 形态 | OpenCV 对应 |
| --- | --- | --- |
| 画矩形框 | `rectangle(x,y,w,h,R,G,B[,thickness])` | `cv2.rectangle`（thickness=-1 填充=FILLED） |
| 画圆 | `circle(cx,cy,r,R,G,B[,thickness])` | `cv2.circle` |
| 画线 | `line(x1,y1,x2,y2,R,G,B[,thickness])` | `cv2.line` |
| 写文字 | `text('label',x,y,R,G,B[,scale])` | `cv2.putText`（引号内可含逗号） |
| 灰度 | `grayscale` | `cv2.cvtColor(BGR2GRAY)` |
| 均值模糊 | `blur(ksize)`（奇数 1..51） | `cv2.blur` |
| 旋转 | `rotate(90\|180\|270)` | `cv2.rotate` |
| 翻转 | `flip(0\|1\|-1)`（0 上下 / 1 左右 / -1 双向） | `cv2.flip` |

- **GET**：`GET /b/k.png?x-gimg-ops=rectangle(...)|text('person',...)` 即时处理返回（预览）；
- **PUT**：上传即处理落盘（含 `x-gimg=base64` 直传）；与 `x-gimg-crop/resize/format/quality`
  组合，顺序 crop → ops → resize → format；
- **处理另存**：`POST /b/src.png?x-gimg-ops=...&x-gimg-save-as=b/dst.png`——读取源对象执行
  管道后写入新对象（标注结果持久化）；缺 `x-gimg-ops` 报 400；
- **文字渲染**：默认内置 ASCII bitmap 字体；配置 `s3.image_font: /path/font.ttf` 后支持
  中文等 TrueType 字形（如 Windows `C:/Windows/Fonts/msyh.ttc`、Linux `NotoSansCJK`）。

### 语法与纠错

- **裸名合法**：无参操作可省括号——`grayscale` ≡ `grayscale()`（两种写法等价）；
- **非法管道显式 400**：未知操作名、括号不闭合、参数个数/取值非法（如 `blur(4)` 偶数核）
  一律返回 `400 InvalidArgument`，**不再静默透传原图**（此前需用「结果 md5 ≠ 原 md5」判别生效）；
- 操作管道**多核并行 + 逐像素直写**：`blur` 为可分离两遍滑动窗口（每像素 O(1)，与核大小无关），
  `grayscale/rotate/flip/resize` 走 RGBA 字节直读直写路径，大图（4096×3072 级）多步管道
  由秒级降至亚秒级。

### 结果磁盘缓存（GET 加工链路）

`s3.image_cache: true`（默认开）时，GET 加工结果落盘缓存于 `<db_dir>/sys/gimg_cache/`：

- **缓存键** = sha256(bucket + key + versionId + etag + 参数规范化串)——对象被覆盖/删除后
  etag/version 变化，旧条目自然失效，同参数请求直接命中（并发同参数请求单飞，只处理一次）；
- **容量治理**：`s3.image_cache_mb`（默认 1024，`-1` 不限）超限按**最久未用淘汰**（访问 touch），
  生命周期扫描周期顺带回收；
- **观测响应头**：`X-Gimg-Cache: miss|hit`（是否命中缓存）、`X-Using-Time`（请求整体耗时）、
  `X-Gimg-Ops-Time`（图片管道纯处理耗时；两者差距大 = 网络/传输开销，都大 = 解码编码开销）；
- 缓存文件为**明文派生图**（区别于底层加密 .db），属系统数据区；敏感场景可 `image_cache: false` 关闭。

## v1.3.11：分片直写存储 / Range 读 / 裁剪融合 / 管理面异步任务 / 空间回收

### 存储层（默认参数变更 + 零拷贝合并）

- `s3.max_object_mb` 默认 **16384（16GB）**，`s3.chunk_kb` 默认 **8192（8MB）**；
- 分片上传（multipart）内容流式按 8MB 分块直接落桶分块表暂存区（行键
  `key, uploadId, partNumber*2^20+i`）——内存占用与分片大小无关；
- `CompleteMultipartUpload` **零数据拷贝**：versioning 桶以 uploadId 为版本号原地转正；
  非 versioning 桶一条 `UPDATE` 改写暂存行 version_id；小对象（≤ inline 阈值）装配进
  content 列后清理；
- 对象行 `manifest` 列记录各 part 的 `[startSeq, nChunks, size, chunkSize]`，GET Range
  据此直定位分块；v1.3.10 前的稠密布局对象自动兼容读；
- PUT/DELETE 版本域收窄为 `version_id=''`，不再误删进行中上传的暂存行。

### Range 读（HTTP 206）

```
curl -H "Range: bytes=100-199" .../big.bin     # 206 + Content-Range: bytes 100-199/22021019
curl -H "Range: bytes=-100"  .../big.bin       # 末 100 字节
curl -H "Range: bytes=999999999-" .../big.bin  # 416 InvalidRange
```

### 图片裁剪融合 blend

`blend('key'[,x,y[,alpha[,cx,cy,cw,ch]]])`：同桶对象 `key` 解码为融合源；可选
`(cx,cy,cw,ch)` 先裁剪；按权重 `alpha`（0..1，默认 1）贴入当前画布 `(x,y)`
（逐通道 `out = base*(1-w) + src*w`，w = alpha×源像素不透明度，≈ `cv2.addWeighted`）。

```
GET /b/base.png?x-gimg-ops=blend('logo.png',10,20)                # 水印贴入
GET /b/base.png?x-gimg-ops=blend('logo.png',0,0,0.5)              # 半透明融合
GET /b/base.png?x-gimg-ops=blend('logo.png',5,5,1,10,10,20,10)    # 裁剪 20x10 后贴入
```

**权限边界**：融合源恒为**同桶**对象；`x-gimg-save-as` 只接受同桶 key（带 bucket 前缀
一律 400）——图片处理链路不再提供任何跨桶读写能力（v1.3.11 安全修复）。

### 管理面异步任务（super 专用）

```
SUBMIT S3 TEXT SEARCH <bucket> MATCH '<text>' [PREFIX '<p>'] [LIKE '<pat%>']
  [SIZE (>|>=|=|<|<=) n | SIZE BETWEEN a AND b] [MODIFIED (BEFORE|AFTER) '<ts>']
  [CREATED (BEFORE|AFTER) '<ts>'] [LIMIT n] [CALLBACK url ...] [EVERY ...]
SUBMIT S3 FILE SEARCH <bucket> [同上过滤（无 MATCH）] [LIMIT n] [...]
SUBMIT S3 DELETE <bucket> [同上过滤] [DRY RUN] [LIMIT n] [...]
```

- TEXT SEARCH：文本文件**内容级**检索（content-type 语义 + 头部字节嗅探双判定，
  > 64MB 跳过；大小写不敏感），返回 `bucket/key/size/line_no/line_text`；
- FILE SEARCH：元数据级检索，返回 `bucket/key/size/content_type/etag/modified/created`；
- DELETE：异步批量删除（尊重对象锁 / WORM：被锁对象结果为 `locked`）；`DRY RUN` 只报告；
- 时间语义：MODIFIED = 最新版本写入时间；CREATED = 全版本最早写入时间；
- 任务走异步引擎（`FETCH QUERY RESULT '<id>'` 取结果、CALLBACK 回调、EVERY 周期链
  与 SQL 任务一致）。

### 空间回收（SQLite 删除只挂 freelist 不缩文件）

```
SHOW S3 SPACE            -- page_size / page_count / freelist_pages / free_bytes / auto_vacuum
S3 VACUUM                -- 增量：每步 256 页短写事务（WAL 下读不受影响，写仅单步排队）
S3 VACUUM FULL           -- 排他重建整个库文件（维护窗口执行），并把存量库切到增量模式
```

新部署的系统库自动 `auto_vacuum=INCREMENTAL`；存量库执行一次 `S3 VACUUM FULL` 后，
日常空间释放都可走免长锁增量路径。后台生命周期扫描顺带自动回收（空闲 > 128MB 且
> 10% 文件大小触发，单轮至多 1GB）。
