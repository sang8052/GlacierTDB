# GlacierTDB S3 对象存储路线（后续规划）

> 状态：**设计稿，未实现**。在现有 MySQL 协议网关之上，为同一份数据目录增加 **S3 兼容对象存储**能力——
> 「一个进程，两种协议」：3309 说 MySQL，`:9000` 说 S3。
> 延续项目红线：纯 Go、无 CGO、零外部中间件、单二进制。

---

## 1. 目标与定位

| # | 能力 | 说明 |
| --- | --- | --- |
| 1 | **S3 协议兼容** | 标准 S3 REST API（HTTP 暴露），AWS **AK/SK（SigV4）认证**，aws-cli / SDK / minio-client 直接用 |
| 2 | **扩展：base64 读写** | `PUT/POST ?encoding=base64`：body 为 base64 → 落盘 bytes；`GET ?encoding=base64`：读 bytes → 返回 base64（方便脚本/表单/纯文本管道搬运二进制） |
| 3 | **扩展：图片缩放** | `GET ?resize=<w>x<h>&format=jpg/png/webp`：服务端实时缩放（缓存落盘可选） |
| 4 | **扩展：QoS 限速** | 按 AK 的请求速率（QPS）与**带宽**（bytes/s）双限速，令牌桶实现 |
| 5 | **存储形态** | minio 风格：对象数据**直接写硬盘文件**；元数据（bucket / ak·sk / object metas）存 SQLite（`glacier-s3` 内置库） |
| 6 | **多机冗余** | 对象多副本 + 元数据同步，零中间件复制 |

## 2. 架构

```
   aws-cli / SDK / minio-client          mysql / Navicat / ORM
            │ S3 REST + SigV4                     │ MySQL 协议
            ▼                                     ▼
┌──────────────────────────┐        ┌──────────────────────────┐
│  S3 网关（:9000，新增）   │        │  MySQL 网关（:3309，现有）│
│  SigV4 校验 │ QoS 令牌桶  │        │  探活/改写/管理面（现有）  │
│  base64│resize           │        └───────────┬──────────────┘
├──────────────────────────┴────────────────────┤
│  元数据：glacier-s3 库（SQLite，复用多库/每库写锁）│
│    buckets / access_keys / objects / qos_rules │
├───────────────────────────────────────────────┤
│  对象数据：db_dir/s3/<bucket>/<object-path>     │
│  （直接写硬盘，minio 风格；大文件零 SQLite 负担） │
└───────────────────────────────────────────────┘
```

要点：

- **数据与元数据分离**：对象字节直接落文件（上传直写、下载直读，支持大文件）；大小、ETag(MD5)、Content-Type、自定义 meta 存 `objects` 表；
- **认证**：手写 SigV4 校验（HMAC-SHA256 签名链，约 200 行，无外部依赖）；AK/SK 由管理面 SQL 管理；
- **写路径**复用「每库一把写锁」的并发模型（`glacier-s3` 库即一个库）。

## 3. 配置（规划）

```yaml
s3:
  enable: true
  listen: 0.0.0.0:9000
  data_dir: ""            # 默认 <db_dir>/s3
  default_quota_gb: 0     # 每 bucket 配额（0=不限）
  tls: ""                 # 可选证书目录；默认明文（内网）
```

## 4. 管理（复用现有管理面）

```sql
USE GlacierTDB;

SHOW S3 BUCKETS;                          -- bucket 列表（大小/对象数/配额）
SET S3 USER <ak> = '<sk>';                -- 创建/更新 AK/SK
SET S3 USER <ak> = '';                    -- 删除
SET S3 QOS <ak> QPS = 100, KBPS = 20480;  -- 限速（0=不限）
SET S3 QUOTA <bucket> = 100;              -- GB
SELECT * FROM s3_objects WHERE bucket='img' AND size > 1048576;
```

## 5. API（首版子集）

| 操作 | API |
| --- | --- |
| ListBuckets | `GET /` |
| CreateBucket / DeleteBucket | `PUT /<bkt>` / `DELETE /<bkt>` |
| PutObject（含 base64 扩展） | `PUT /<bkt>/<key>`（body=bytes；`?encoding=base64` 时 body=base64） |
| PostObject | `POST /<bkt>/<key>`（同上，表单友好） |
| GetObject（含 base64 / resize 扩展） | `GET /<bkt>/<key>[?encoding=base64][&resize=200x&format=webp]` |
| HeadObject / DeleteObject | `HEAD` / `DELETE /<bkt>/<key>` |
| ListObjectsV2 | `GET /<bkt>?list-type=2&prefix=&max-keys=` |
| 多对象删除 | `POST /<bkt>?delete` |

扩展响应头：`X-Glacier-Encoding: base64`、`X-Glacier-Resized: 200x`、限速命中返回 `503 Slow Down`。

图片缩放：`golang.org/x/image/draw`（纯 Go，唯一新增依赖）+ 标准库 jpeg/png；webp 视依赖情况后置。

## 6. 多机冗余（阶段 3）

原则：**不引入外部协调服务**（延续零中间件）。

- **对象副本**：`PUT` 按 bucket 的 `replicas` 配置同步写 N 台成员（成员表存元数据库；Go 原生 HTTP 转发，写多数成功即返回 200，落后者由对账任务补齐）；
- **元数据**：单主写入 + 版本号（`epoch`）拉取同步；主故障时按成员序号提升（冷库场景允许秒级窗口，不做自动脑裂防护的强一致——诚实声明）；
- **读**：任意副本可读（对象不可变语义，读扩展天然成立）；
- 与「固化只读多实例」路线衔接：固化库可加入集群作为只读成员。

## 7. 阶段划分

| 阶段 | 内容 | 规模估计 |
| --- | --- | --- |
| **S1** | S3 核心协议（上表 API）+ SigV4 + 硬盘落盘 + 元数据库 + 管理面 SQL | 主体工作 |
| **S2** | 扩展：base64 读写、图片缩放、QoS 限速（QPS+带宽）、bucket 配额 | 中 |
| **S3** | 多机冗余（副本写 + 元数据同步 + 对账） | 大 |

每阶段完成后并入 `tests/` 黑盒回归（aws-cli 容器作为测试客户端）。

## 8. 明确不做（防范围蔓延）

- ✗ 完整 S3 兼容面（版本控制/生命周期/事件通知/Select…按需再加）；
- ✗ 纠删码（副本已满足冷库冗余，EC 复杂度不成比例）；
- ✗ 外部协调服务（etcd/consul）——违背零中间件；
- ✗ 对象级强一致多主写——冷库写入一次性，单主足够。
