# GlacierTDB 部署运维手册

> 覆盖：部署（Docker / 裸机 / systemd）、升级、备份恢复、固化只读多实例、日常监控、故障排查。
> 配置项详见 [配置说明.md](配置说明.md)，系统管理命令详见 [系统SQL.md](系统SQL.md)。

---

## 1. 部署

### 1.1 Docker Compose（推荐）

```yaml
# docker-compose.yml
services:
  glaciertdb:
    image: glaciertdb:latest        # 或自行 build: .
    container_name: glaciertdb
    ports:
      - "3309:3309"
    volumes:
      # 必须挂「目录」而非单个 .db 文件（WAL 需在同目录创建 -wal/-shm）
      - /srv/glacier/data:/data
    restart: unless-stopped
```

```bash
docker compose up -d
mysql -h <主机> -P 3309 -uglacier -p<密码> -e "SELECT glacier_version;"
# MQTT（可选）：mqtt客户端连 <主机>:3309（tcp 嗅探 / ws /mqtt / mode:mqtt），
# 或在 config 的 mq.mqtt.listen 配独立端口（如 0.0.0.0:1883，tcp+ws 同端口）
```

### 1.2 裸机（静态二进制）

```bash
# linux amd64 / arm64（Ubuntu 24.04 实测），产物零依赖
# 配置文件与二进制同目录时 -config 可省：默认依次查找 ./config.yaml → exe 同目录 → /app/config.yaml
./glaciertdb-linux-amd64 -db-dir /srv/glacier/data
./glaciertdb-linux-amd64 -config /etc/glaciertdb/config.yaml -db-dir /srv/glacier/data
```

Windows：`glaciertdb-windows-amd64.exe`（配置文件放 exe 同目录双击/裸起即可；
`db_dir` 支持原生路径 `H:\glacier\data`、正斜杠、相对路径；目录需事先创建）。

### 1.3 systemd 示例

**v1.3.12 起推荐看门狗形态**（`Type=notify` + `WatchdogSec`，程序内每
WatchdogSec/2 对系统库做一次 `SELECT 1` 并发 `WATCHDOG=1` 心跳——探活探真依赖，
存储层卡死 30 秒内自动重启；完整样例含 GOMEMLIMIT 按内存档位建议，见仓库
`deploy/glaciertdb.service`）：

```ini
# /etc/systemd/system/glaciertdb.service
[Unit]
Description=GlacierTDB (MySQL protocol over SQLite)
After=network.target

[Service]
Type=notify
NotifyAccess=main
WatchdogSec=30
ExecStart=/usr/local/bin/glaciertdb -config /etc/glaciertdb/config.yaml
Restart=always
RestartSec=3
StartLimitIntervalSec=120
StartLimitBurst=5
# 内存档位建议（防 OOM kill 后未落盘批次悬空）：1GB→700MiB / 2GB→1536MiB / 4GB→3GiB
Environment=GOMEMLIMIT=1536MiB
LimitNOFILE=65535

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload && systemctl enable --now glaciertdb
journalctl -u glaciertdb -f          # 运行日志（stderr）
```

### 部署检查清单

- [ ] `db_dir` 目录已创建且可写（WAL 依赖；系统库/密钥文件同目录）
- [ ] 首次启动日志出现 `listening on ...` 与默认库自动创建
- [ ] 客户端连通性 + `SELECT glacier_version;`
- [ ] 已执行 `USE GlacierTDB; SET PASSWORD='<强口令>';`（或确认 glacier.json 就位）
- [ ] 需要 SQL 审计时配置 `log.sql_log_file`
- [ ] 启用 S3/Redis/RabbitMQ/MQTT 时防火墙放行 9000 / 3309 对应协议（3309 为多协议复用：MySQL/RESP/AMQP/MQTT-tcp/MQTT-ws）；启用 `mq.mqtt.listen` 时另放行该端口
- [ ] 内网环境或已启用 TLS（v1.3.12 `tls:` 配置段；未启用 TLS 勿暴露公网）

## 2. 升级

1. 替换二进制 / 镜像（数据在 `.db` 文件中，与程序解耦）；
2. 重启；配置不兼容项会报错退出（无静默丢弃）；
3. 回滚 = 换回旧二进制重启（SQLite 文件向后兼容）。

> 跨库写并行的每库写锁、WAL 格式均为 SQLite 标准行为，升级不改存储格式。
>
> **历史升级注意**：① 空字符串结果集语义修复——此前 `''` 会被客户端读成 NULL，升级后如实返回 `''`，依赖"空串即 None"的下游需自查（pydantic 等强类型层不再 500）；② 并行查询 hint 自此真实生效（此前被注释剥离静默吞掉）；③ 新增 MySQL 函数（MD5/SHA 族等）注册于每个后端连接，无启动开销变化。

## 3. 备份与恢复

**在线备份（推荐，v1.3.12 起）**：`-backup` 子命令——服务运行中对全部库（sys/ + user/）
逐个 `VACUUM INTO` 快照单文件，WAL 读快照**不阻塞业务写入**；全部成功后原子落位
（旧一代轮转为 `<目标>.old`，单库失败整体中止不留半成品）；默认对每个产物做
`integrity_check` + 对象数比对（`-backup-verify=false` 跳过换速度）：

```bash
./glaciertdb -config /etc/glaciertdb/config.yaml -backup /srv/backups/glacier-$(date +%F)
# 备份产物 = 普通 SQLite 单文件（加密部署下为同口令密文单文件）
```

配套 systemd 定时样例：`deploy/glaciertdb-backup.{service,timer}`（每天 04:30），
`systemctl enable --now glaciertdb-backup.timer` 即用。

**离线备份（最稳）**：停服后直接拷贝

```bash
systemctl stop glaciertdb
tar czf glacier-$(date +%F).tgz /srv/glacier/data/    # .db + -wal + -shm + glacier.json
systemctl start glaciertdb
```

**恢复**：在线备份产物 = 拷贝文件回 `db_dir`（sys/ 与 user/ 对应子目录）后启动；
整目录 tar 包解包到 `db_dir` 启动即用——没有更快的数据库恢复方式了。
**注意**：运行中直接 `cp -r` 数据目录**不是**安全备份（拷贝期间 checkpoint 可能得到
主库与 `-wal` 不一致的组合）——运行中备份必须走 `-backup` 子命令。

**策略建议**：冷归档场景按天/周全量备份即可。备份务必包含整个 `db_dir`——除业务库外还有：
系统库（`glacier_auth.db` 账号权限 / `glacier_s3.db` / `glacier_kv.db` / `glacier_mq.db` / `glacier_meta.db` 列类型映射）、
`glacier.json`（改密持久化）、`glacier_s3.key`（S3 AK/SK 加密主密钥）、`glacier_rsa.pem`
（caching_sha2 RSA 密钥）——**密钥文件丢失 = 密钥/密码体系不可恢复**（`-backup`
覆盖 sys/ + user/ 的 `.db`，密钥文件请另行纳入备份）。

## 4. 固化与只读多实例（读扩展）

冷数据归档完成后，转为不可变单文件：

```sql
PRAGMA journal_mode=DELETE;   -- 离线执行：退出 WAL
VACUUM;                       -- 压实
```

固化后的 `.db`：

- 可 `mode=ro` 只读打开（免 `-wal/-shm`，可放只读介质）；
- **复制文件 + 起多个网关实例 = 读扩展**，无复制协议。

## 5. 日常监控

| 手段 | 命令 / 位置 |
| --- | --- |
| 版本与配置 | `USE GlacierTDB; SHOW SERVER CONFIG;`（含 `current_connections`、并发热改值） |
| 连接与事务 | `SHOW CLIENTS; SHOW TRANSACTIONS;`（持锁/事务时长/最近语句） |
| 慢查询 | 运行日志（`slow_query_ms` 阈值，`docker logs` / journalctl） |
| 全量 SQL 审计 | `log.sql_log_file` JSON 行（status/cost_ms/rows/error） |
| 内存 | `docker stats` / systemd（配 `memory_limit_mb` 软上限） |

踢异常连接：`KILL <conn_id>;`；动态压测调参：`SET GLOBAL_THREADS=…`。

## 6. 故障排查对照表

| 报错 / 现象 | 原因与处置 |
| --- | --- |
| `init sqlite backend: db dir ... 不存在或不是目录` | `db_dir` 未创建或不可写 → 建目录、挂卷挂目录不挂文件 |
| `unable to open database file`（误导性强） | 目录只读 / 挂载了单个 `.db` 文件 → 挂目录 |
| `database is locked`（连接建立时） | 新连接 DSN 初始化撞上活动写锁；已内置 busy_timeout 前置 + 重试，偶发重连即可；持续出现检查是否有外部进程同时打开该文件 |
| `1045 Access denied` | 密码不对——注意 `glacier.json` 持久化密码优先于配置文件；删该文件回到配置文件密码 |
| `3119 ... blocked (brute-force)` | 账号/IP 被防爆破锁定：`UNLOCK ACCOUNT/IP` 管理面解锁，或 CLI 旁路解锁（见下）；**本机 127.0.0.1 永不会被锁** |
| `1064 ... no such table: xxx.yyy` | 客户端跨库引用非当前库名前缀（不支持跨库 JOIN） |
| 客户端「连不上」但端口通 | 查 SQL 审计日志看客户端实际发的语句；探活/SHOW/系统库兼容已覆盖绝大多数，仍报错请提 issue 附日志 |
| 写卡住 | `SHOW TRANSACTIONS;` 看持锁连接 → `KILL` 之；注意 `SET AUTOCOMMIT=0` 连接的首条写会持锁到 COMMIT |
| 内存增长 | 检查 `max_result_rows` 是否被大查询打满；配 `memory_limit_mb`；连接数 × `cache_size_kb` 估算页缓存总量 |
| 3309 连接被立即断开 | 检查是否配置了 `mysql.enable: false`（MySQL 面关闭时 MySQL 客户端连接即断；RESP/AMQP/MQTT 不受影响） |

### 6.1 CLI 旁路解锁（防爆破锁死自救）

某客户端密码配错可能触发防爆破锁定（默认：单 IP 30 次 / 单账号 5 次失败）。账号被锁导致
**管理面也无法登录**时，无需停服——命令行直连 `glacier_auth` 系统库小事务解锁：

```bash
# 与服务同机执行（服务保持运行；WAL 多进程并发安全，不抢目录锁）
./glaciertdb -db-dir /data -unlock-user app_writer     # 解锁账号（自动锁/手动锁/失败计数）
./glaciertdb -db-dir /data -unlock-ip 10.1.2.3         # 解锁 IP（含防火墙解封）
./glaciertdb -db-dir /data -show-locks                 # 查看当前锁定列表
```

> **本机回环地址（127.x / ::1 / localhost）永不锁定**：本机客户端密码配错不会把
> 127.0.0.1 锁死（审计照记，账号维度计数不受影响）。

## 7. 安全边界（必读）

- **用户权限系统**：账号入库（`glacier_auth.db`）、库/表/IP 授权、防爆破自动锁 IP/账号
  （可选 ufw/iptables/firewall-cmd 系统层封锁、登录失败 HTTP 告警；本机回环地址永不锁定）；
  无 TLS、无列级权限——**仅限内网可信环境**，公网暴露请前置带认证的代理（如 nginx stream + TLS）；
- 默认超级用户 `glacier` 请设强口令；只读接入用 `glacier_ro` 或自建 `READONLY` 账号（回写型工具误连时保护归档）；
- 登录审计 `SHOW LOGIN ATTEMPTS` / 锁定 `SHOW LOCKED` / 解锁 `UNLOCK …`（或 CLI `-unlock-user/-unlock-ip`）；配置见 [配置说明.md §2.5/§2.9](配置说明.md)。

- **目录分类**：`db_dir/sys/` 存系统库、`db_dir/user/` 存用户业务库——升级启动
  自动归类存量平铺库（日志逐条列明）；备份/恢复照常整目录拷贝。
