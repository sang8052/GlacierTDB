# GlacierTDB 消息队列手册（RabbitMQ 能力 · AMQP 0-9-1 + MQTT 接入，v1.3.3）

> 通过 `mode:rabbitmq` 在 **3309 同端口**提供 AMQP 0-9-1 基本队列能力：exchange
> （direct / fanout / topic）+ queue + binding、publish / consume / ack / nack / reject、
> prefetch、**publisher confirm 发布确认与 mandatory 回退（v1.3.2）**、
> **持久化消息与消费游标落 SQLite（重启不丢）**。
> 定位：基本队列通知 / 分发——不做镜像集群、不做事务性队列（设计红线）。

---

## 1. 端口复用与连接

| 进入方式 | 说明 |
| --- | --- |
| `mode:rabbitmq` 声明行 | 连接首行 ASCII 单行 `mode:rabbitmq`，随后按 AMQP 握手 |
| AMQP 魔数嗅探 | 原生客户端（pika / amqp091-go / RabbitMQ SDK）发送 `AMQP\x00\x00\t\x01` 即自动进入 |
| 默认 | 静默等握手 → MySQL（零改动） |

- 认证：SASL **PLAIN**（`AUTH <user> <password>` 语义），沿用统一账号体系——host 授权、
  账号锁定、登录审计、防爆破计数与 MySQL 侧一致；vhost 忽略（接受任意值）；
- **命名空间 = 登录账号**：队列 / 交换机 / 消息按账号隔离。

```python
import pika
conn = pika.BlockingConnection(pika.ConnectionParameters(
    host="10.25.250.30", port=3309, heartbeat=0,
    credentials=pika.PlainCredentials("glacier", "iloveyou~")))
ch = conn.channel()
```

## 2. 能力矩阵

| 类别 | 支持 |
| --- | --- |
| exchange | `direct` / `fanout` / `topic` 声明与删除；默认交换机 `""`（routing key = 队列名直达） |
| queue | 声明（durable / exclusive / auto-delete 参数接受）、绑定 / 解绑、purge、删除 |
| 生产 | `basic.publish`（属性原样透传：content-type / delivery-mode / correlation-id 等；`mandatory` 位支持回退，v1.3.2） |
| 消费 | `basic.consume`（push）/ `basic.get`（pull）/ `basic.cancel` |
| 确认 | `basic.ack`（含 multiple）/ `basic.nack`（requeue 重投 + redelivered 标志）/ `basic.reject` / `basic.recover` |
| 发布确认 | `confirm.select` → 逐条 `basic.ack`（发布失败 `basic.nack`，v1.3.2）+ mandatory 不可路由 `basic.return`（§3） |
| 流控 | `basic.qos` prefetch-count（未 ack 达上限暂停投递） |
| 其它 | `tx.select/commit/rollback` 空实现；`channel.flow` 回显 |

**topic 路由**：`*` 匹配恰好一个词、`#` 匹配零或多个词（`.` 分词，RabbitMQ 语义）。

**已知边界**：事务性队列、镜像/仲裁队列不在范围（FEATURE 红线）；`immediate` 位忽略。

## 3. 发布确认与回退（v1.3.2）

**publisher confirm**：`confirm.select`（nowait 支持）后通道进入确认模式，每条 publish
按通道内发布序号（delivery-tag，从 1 递增）逐条回 `basic.ack`；发布失败（如超
`max_message_mb`）回 `basic.nack`：

```python
ch.confirm_delivery()   # confirm.select → confirm.select-ok
ch.basic_publish(exchange="", routing_key="q", body=b"...")   # basic.ack 收到后才返回
```

**mandatory 回退**：`basic.publish` 带 `mandatory=true` 且一条队列都没路由到时，
服务端以 `basic.return`（reply-code **312 NO_ROUTE**，exchange / routing-key 原样）+
原 header / body 回退给发布方；路由成功则不回退。confirm 模式下回退后**仍发 ack**
（"已处理"语义，对齐 RabbitMQ）：

```python
ch.add_on_return_callback(lambda c, m, p, b: print(m.reply_code, m.exchange, m.routing_key, b))
ch.basic_publish(exchange="ex", routing_key="no.route", body=b"back", mandatory=True)
conn.process_data_events(time_limit=2)   # 回退回调在事件循环中分发
# pika confirm 模式下回退会汇总抛出 UnroutableError（basic.return 先回、basic.ack 后到）
```

- 未知交换机按「不可路由」处理（不回 404 通道错误，mandatory 时同样回退）；
- 回退消息不落盘、不重试——发送方收到后自行处置。

## 4. 持久化与恢复

- **消息与消费游标实时落 SQLite**（`<db_dir>/glacier_mq.db`，WAL）：publish 即落盘；
- durable 队列 + persistent 消息（`delivery_mode=2`）**容器重启后不丢**（run_all.sh 步骤 3.5 实测）；
- 未确认（unacked）消息在连接断开 / 通道关闭 / `basic.nack(requeue=true)` 时**自动重入队**
  （redelivered 标志置位）；
- `mq.max_message_mb`（默认 32）单条消息上限。

## 5. 管理面观测

## 6. 与异步任务互通（自服务回环）

异步任务的 `CALLBACK 'amqp://…'` 通道可指向本服务自身（FEATURE §4 回环）：

```sql
SUBMIT QUERY 'SELECT 42 AS a'
  CALLBACK 'amqp://glacier:iloveyou~@10.25.250.30:3309/' QUEUE 'glacier_jobs';
-- 任务完成后消息以 persistent 落入 glacier_jobs 队列（默认交换机、routing key = 队列名），
-- 任何消费者 basic.consume/basic.get 即可取走（载荷为任务回调 JSON）。
```

## 7. 配置

```yaml
mq:
  enable: true          # AMQP 服务开关（默认开；false 时 3309 不识别 AMQP）
  max_message_mb: 32    # 单条消息上限
```

## 8. MQTT 接入（v1.3.3，tcp + ws）

- **进入方式**：3309 复用——MQTT CONNECT 首包嗅探（首字节 0x1x）、HTTP `GET /mqtt` WebSocket 升级（RFC 6455）、`mode:mqtt` 声明行；可选独立监听 `mq.mqtt.listen`（tcp 与 ws 同端口）；
- **桥接模型**：MQTT topic `a/b/c` ↔ AMQP routing key `a.b.c`（`mqtt` topic 交换机，durable）；
  订阅过滤器 `+`/`#` ↔ binding `*`/`#`——MQTT 客户端与 AMQP 客户端（pika/amqp091-go）**双向互通**；
- **QoS**：0（noAck 即发即忘）与 1（PUBACK）；clean_session=0 时队列持久，离线消息重连补投；
  QoS2 按简化握手（PUBCOMP）应答；
- **保留消息**：retain=1 落 `mqtt_retains`（重启不丢），新订阅命中过滤器即时补发（空 payload 保留 = 删除）；
- **遗嘱**：CONNECT 携带 will 的连接异常断开（非 DISCONNECT）时按 will QoS/retain 发布；
- **keepalive**：读超时 1.5×，超时断开（触发遗嘱）；PINGREQ/PINGRESP 支持；
- **认证**：统一账号体系（CONNECT username/password，防爆破/锁定/host 授权与 MySQL/Redis/AMQP 一致），
  命名空间 = 账号名；版本 3.1（MQIsdp）/3.1.1，5.0 回 CONNACK 0x01；
- 每连接一个 `mqtt.<clientID>` 队列 + 单消费者按全部过滤器分发（多订阅不丢消息）；
  管理面 `SELECT * FROM mqtt_retains`（namespace/topic/bytes/qos/ts）。

## 9. 客户端兼容

pika（Python）与 amqp091-go（Go，RabbitMQ 官方风格客户端）实测互通；Java / .NET / Node 的
AMQP 0-9-1 客户端按协议兼容预期可用。

> 已知客户端缺陷：pika 1.4.4 在 `connection.close()` 的关闭握手处理上有自身 bug
>（会话内全部操作正常；对任何 AMQP 服务端同样复现），清理连接时建议 try/except 包裹。
