# GlacierTDB 配置手册

> 配置文件为 YAML（默认路径 `/app/config.yaml`，容器内）；
> **所有项均可省略**，省略时使用内置默认值。
> 改配置后重启生效；运行期可用管理面 SQL 热改部分参数（见 [系统SQL.md](系统SQL.md)）。

---

## 1. 完整配置示例（含默认值）

```yaml
listen: 0.0.0.0:3309        # 监听地址
db_dir: /data               # 库目录：一个库 = 目录下一个 <库名>.db 文件
default_db: backup          # 连接未指定库时的默认库（不存在则自动创建）
server_version: "8.99.999"  # 对外呈现的 MySQL 版本号

# ---- 资源保护 ----
memory_limit_mb: 0     # Go 运行时软内存上限（0 = 不限制）
max_connections: 64    # 最大并发客户端连接数（超限直接断开）

# ---- 并发模型：读并发多线程（可按库限流）；写单库单线程互斥（多库写入并行）----
concurrency:
  global_threads: 0              # 全局并发执行上限（读写共享，0=不限）
  per_db_read_threads: 0         # 全局默认：单库读并发上限（0=不限）
  per_db_read_threads_override:  # 按库覆盖（可选）
    # backup: 8
    # logs: 2

# ---- 多核并行查询 ----
parallel_query:
  disable: false         # true = 彻底关闭并行查询
  workers: 0             # 自动触发并行度（0 = CPU 核数，上限 32）
  scan_rows: 1000000     # 自动触发阈值：估算行数 ≥ 此值才并行（0 = 关闭自动触发）

# ---- 异步查询引擎（详见 docs/异步任务.md）----
async_query:
  enable: true                  # 段缺失时同样默认启用（与 kv/mq 一致）
  workers: 2                    # worker 提示值
  metrics_interval_sec: 30      # WHEN 资源采样周期（最低 10）
  result_retain_sec: 60         # 结果默认保留秒数（RETAIN 按任务覆盖）
  default_timeout_sec: 1800     # 默认等待超时（TIMEOUT 覆盖）
  jobs_dir: ""                  # 结果目录（默认 <db_dir>/jobs）
  jobs_dir_max_gb: 0            # 结果目录水位上限（0 = 不限）
  callback_max_inline_kb: 64    # 分片回调单片数据内联上限
  # nodejs_path: ""             # SCRIPT 后处理 runtime（空=禁用该类脚本）
  # python_path: ""
  # php_path: ""                # SCRIPT 后处理 runtime（.php；空=禁用）

# ---- 认证 ----
auth:
  user: glacier             # 固定值，配置其他名字会被忽略
  password: "changeme"      # mysql_native_password；管理面 SET PASSWORD 热改后
                            # 以 <db_dir>/glacier.json 为准（重启亦是）
  readonly_user: glacier_ro     # 只读账号：同等认证，仅允许查询与查看
  readonly_password: "changeme" # 只读账号密码（空 = 禁用只读登录）；热改同管理员

# ---- SQLite ----
sqlite:
  synchronous: NORMAL       # OFF | NORMAL | FULL | EXTRA（持久化强度）
  busy_timeout_ms: 5000     # 锁等待兜底（主策略是网关层每库写锁）
  cache_size_kb: 256        # 每连接页缓存
  max_result_rows: 1000000  # 单查询返回行数上限（内存保护）

# ---- 日志 ----
log:
  level: info               # debug | info | warn | error
  slow_query_ms: 200        # 慢查询阈值（超过则记入运行日志）
  sql_log_file: ""          # SQL 审计日志路径（空=关闭），如 /data/sql.log

# ---- MySQL 协议服务（3309 复用端口上的 MySQL 面）----
mysql:
  enable: true              # false = 3309 不再服务 MySQL（RESP/AMQP/MQTT 不受影响；
                            #        mysql/kv/mq 全关时不监听 3309，适合纯 S3 等独立部署）

# ---- 键值/队列（mode:redis 同端口 RESP；详见 docs/键值队列.md）----
kv:
  enable: true            # RESP 服务开关（默认开；false = 纯 MySQL）
  max_memory_mb: 64       # 内存上限（0 = 不限）
  eviction: allkeys-lru   # allkeys-lru | volatile-lru | noeviction
  scan_interval_sec: 5    # TTL 主动扫描周期

mux_sniff_ms: 300         # 端口复用嗅探窗口；等待首包识别 mode:/RESP/AMQP，超时按 MySQL

# ---- 消息队列（mode:rabbitmq 同端口 AMQP 0-9-1；详见 docs/消息队列.md）----
mq:
  enable: true            # AMQP 服务开关（默认开；false 时 3309 不识别 AMQP）
  max_message_mb: 32      # 单条消息上限
  server_version: "3.13.0"   # 对外宣称的 RabbitMQ 版本串
  mqtt:                   # MQTT 接入：tcp+ws 桥接进 mqtt topic 交换机
    enable: true          # 开关（依赖 mq.enable）
    listen: ""            # 可选独立监听（tcp+ws 同端口，如 0.0.0.0:1883；空=仅 3309 复用）
    ws_path: /mqtt        # 3309 上 WebSocket 升级路径

# ---- 时序冷压缩：points 超龄数据自动 gzip 固化，查询自动解冻 ----
timeseries:
  cold_after_days: 0      # 数据年龄超过 N 天自动冷压缩（0 = 关闭自动策略，仅手动 COMPRESS COLD）
  cold_scan_min_sec: 600  # 后台扫描周期（最低 60）

# ---- S3 对象存储（可选模块；详见 docs/S3对象存储.md）----
s3:
  enable: false             # 开关（默认关）；开启后起独立 HTTP(S) 监听器
  region: "*"               # '*' / 空 = 客户端任意 region；具体值 = 签名 scope 必须一致
  endpoints:
    - listen: 0.0.0.0:9000          # HTTP（可配多个端点 / HTTPS 独立端口）
      # tls: true                   # HTTPS
      # cert_file: /data/certs/wildcard.pem
      # key_file: /data/certs/wildcard.key
      server_names: []              # virtual-host 后缀（客户端访问主机名）
  max_object_mb: 16384      # 单对象上限（默认 16GB；-1 = 不限制）
  abort_incomplete_days: 7  # 未完成分片上传自动回收天数（0 = 关闭）
  inline_max_kb: 64         # 内联存储阈值（超过走分块表）
  chunk_kb: 8192            # 分块大小（默认 8MB）
  default_owner: glacier    # 建桶 / 签发密钥未指定属主时的默认用户
  limits:                   # 限速（0 = 不限）：单连接 / 用户总带宽（多连接合并）/ 用户并发
    per_conn_bps: 0
    per_user_bps: 0
    per_user_conns: 0
  bucket_limits: {}         # 按桶覆盖，如 backup: { per_conn_bps: 1048576 }
  lifecycle_interval_sec: 3600   # 生命周期（自动删除）扫描周期
  callback_secret: ""       # 上传回调默认 HMAC 密钥
  # image_font: /usr/share/fonts/truetype/dejavu/DejaVuSans.ttf  # 图片文字 ttf 字体（空=内置 ASCII）
  image_cache: true         # 图片预处理结果磁盘缓存（<db_dir>/sys/gimg_cache/）
  image_cache_mb: 1024      # 缓存容量上限 MB（LRU 淘汰；-1 = 不限）
```

## 2. 逐项说明

### 2.1 基础（listen / db_dir / default_db / server_version）

| 项 | 默认 | 说明 |
| --- | --- | --- |
| `listen` | `0.0.0.0:3309` | MySQL 协议监听地址；只本机用改 `127.0.0.1:3309` |
| `db_dir` | `/data` | 库目录。**一个库 = 目录下一个 `<库名>.db` 文件**；目录需事先存在且可写（WAL 需创建 `-wal`/`-shm`）。Windows 支持原生路径 `H:\glacier\data`、正斜杠 `H:/glacier/data`、相对路径 `.\data` |
| `default_db` | `backup` | 客户端连接未指定库时进入的库；不存在自动创建（空文件 + WAL） |
| `server_version` | `8.99.999` | 对外模拟的 MySQL 协议版本（`SELECT @@version` 返回值）。注意与 GlacierTDB 自身版本（`SELECT glacier_version`，编译于代码常量，当前 `1.3.10.beta`）区分 |

### 2.2 资源保护（memory_limit_mb / max_connections）

| 项 | 默认 | 说明 |
| --- | --- | --- |
| `memory_limit_mb` | `0` | Go 运行时软内存上限（等价 `GOMEMLIMIT`）：GC 更积极回收，逼近上限时降低吞吐而非 OOM。0 = 不限制 |
| `max_connections` | `64` | 最大并发客户端连接数；超限新连接直接断开（日志有 `reject connection` 记录） |

另有一道内存防线：`sqlite.max_result_rows`（见 2.5）。

### 2.3 并发（concurrency）

并发模型：**读并发多线程**（WAL 下读不互斥，可按库限流）；**写单库单线程**（每库一把互斥锁，多库写入天然并行）。

| 项 | 默认 | 说明 |
| --- | --- | --- |
| `global_threads` | `0` | 全局并发执行闸门（读 + 写共享）。压测或 CPU 保护场景用；0 = 不限 |
| `per_db_read_threads` | `0` | 全局默认：单个库的并发读上限。0 = 不限 |
| `per_db_read_threads_override` | `{}` | 按库覆盖全局默认（map：库名 → 上限）。例：热点库给 8、冷库给 2 |

三项均支持管理面热改（`USE GlacierTDB; SET GLOBAL_THREADS=32;`），**热改重启失效回到本文件值**。当前生效值：`SELECT * FROM server_config WHERE name LIKE 'concurrency.%'`。

### 2.4 多核并行查询（parallel_query）

| 项 | 默认 | 说明 |
| --- | --- | --- |
| `disable` | `false` | `true` = 彻底关闭并行查询（hint 与自动触发都失效） |
| `workers` | `0` | 自动触发时的并行度；0 = CPU 核数（上限 32） |
| `scan_rows` | `1000000` | 自动触发阈值：单表可合并聚合语句估算行数 ≥ 此值时自动并行；**0 = 关闭自动触发** |

两种触发方式：hint `/*+ PARALLEL(n) */` 显式指定并行度；无 hint 时按 `scan_rows` 阈值自动触发。
`EXPLAIN PARALLEL <query>` 查看拆分计划。详见 [系统SQL.md §4.1](系统SQL.md)。

### 2.5 认证（auth）

| 项 | 默认 | 说明 |
| --- | --- | --- |
| `user` | `glacier` | **固定值**：写其他名字会被忽略（管理面约定） |
| `password` | `changeme` | `mysql_native_password` 口令。⚠️ 管理面执行 `SET PASSWORD='新密码'` 后：热生效并持久化到 `<db_dir>/glacier.json`，**此后以此文件为准（含重启）**，本项成为首次部署的初始密码 |
| `readonly_user` | `glacier_ro` | 只读账号名：与 `glacier` 同等认证，但仅允许查询与查看——数据面写语句、`BEGIN` 事务、`SUBMIT/CANCEL/DROP QUERY`、管理面变更命令（SET PASSWORD / SET *_THREADS / KILL / VACUUM）一律 `1290` 拒绝 |
| `readonly_password` | `changeme` | 只读账号口令；**置空 = 禁用只读登录**。管理面 `SET PASSWORD FOR glacier_ro='新密码'` / `ALTER USER glacier_ro IDENTIFIED BY '…'` 热改，与 `password` 同一 `glacier.json` 持久化（`readonly_password` 字段，向后兼容） |

> **账号入库**：用户权威存储为系统库 `<db_dir>/glacier_auth.db`（`users` / `user_grants` /
> `user_hosts` 等表），首次启动自动迁移本段与 `glacier.json` 的旧版策略（glacier → 超级用户、
> glacier_ro → 只读用户）；此后 `CREATE USER` / `GRANT` 等管理面 SQL 维护账号，本段仅作
> bootstrap 初始口令与 legacy 镜像（改密仍同步写 `glacier.json` 便于回退）。

### 2.6 SQLite（sqlite）

| 项 | 默认 | 说明 |
| --- | --- | --- |
| `synchronous` | `NORMAL` | `OFF`（最快，掉电可能丢最近事务）/ `NORMAL`（推荐，WAL 下仅断电风险）/ `FULL`（每事务 fsync，最稳）/ `EXTRA` |
| `busy_timeout_ms` | `5000` | SQLite 层锁等待兜底。注意：网关对写已做每库互斥，此项主要防外部进程同时打开同一文件 |
| `cache_size_kb` | `256` | 每连接页缓存；并发连接多时总缓存 ≈ 连接数 × 该值 |
| `max_result_rows` | `1000000` | 单条查询最大返回行数（超出报错），防止误查大表拖垮网关；大结果集请加 LIMIT |

启动时对每个后端连接自动应用（顺序重要，`busy_timeout` 最先）：

```sql
PRAGMA busy_timeout = 5000;
PRAGMA journal_mode = WAL;
PRAGMA foreign_keys = ON;
PRAGMA synchronous  = NORMAL;
PRAGMA cache_size   = -256;
```

### 2.7 日志（log）

| 项 | 默认 | 说明 |
| --- | --- | --- |
| `level` | `info` | `debug`（含每条 SQL） / `info` / `warn` / `error`；输出到 stderr（`docker logs` 可见） |
| `slow_query_ms` | `200` | 语句耗时超过该值记入运行日志 |
| `sql_log_file` | `""` | **SQL 审计日志**：空 = 关闭；如 `/data/sql.log` |

**SQL 审计日志**（调试利器）：每条语句一行 JSON，100MB 自动轮转为 `.old`：

```json
{"ts":"2026-10-15 17:04:10.700","conn":10001,"user":"glacier","remote":"172.18.0.1:38080",
 "db":"backup","admin":false,"cost_ms":7.111,"status":"OK","rows":-1,"affected":1,
 "insert_id":16,"sql":"INSERT INTO t1(name,val) VALUES('audit_row',9.9)"}
```

- `status`：`OK` / `ERROR`（ERROR 时附 `error` 字段，含完整错误消息）
- `cost_ms`：服务端执行耗时；`rows`：返回行数（-1 = 非结果集）；`affected` / `insert_id`：写语句回填
- 客户端探活语句同样记录——客户端报错时对日志即可看到它实际发了什么

### 2.8 查询 QoS（qos）

全系统 + 单库两级配额，读 / 写 / 异步任务执行统一记账：

| 项 | 默认 | 说明 |
| --- | --- | --- |
| `on_exceed` | `wait` | 超限行为：`wait` 排队等待 / `reject` 立即拒绝（返回 1040） |
| `global.qps` / `global.concurrency` / `global.rows_per_sec` | `0` | 全系统每秒查询数（令牌桶）/ 并发执行上限 / 扫描行吞吐上限；0 = 不限 |
| `databases.<库名>` | `{}` | 单库覆盖（同三项），如 `backup: { qps: 500, concurrency: 16 }` |

管理面热改（**重启失效**回到本文件值）：`SET QOS GLOBAL QPS=500` / `SET QOS DB backup QPS=100` / `SET QOS DB backup CLEAR`；
当前值与实时统计：`SHOW QOS` / `SELECT * FROM qos_status`（通过/排队/拒绝计数、当前并发、平均排队毫秒）。

### 2.9 防爆破（lock）

| 项 | 默认 | 说明 |
| --- | --- | --- |
| `enable` | `true` | 关闭后不计数不锁定（登录审计仍记录） |
| `mode` | `mixed` | 锁定维度：`ip_only` 只锁 IP / `account_only` 只锁账号 / `mixed` 独立锁两者（任一触发即拒） |
| `window_sec` | `300` | 失败计数滑动窗口 |
| `max_failures` | `5` | 窗口内失败阈值（通用/账号） |
| `max_failures_ip` | `30` | 按 IP 阈值（默认更宽：多账号共用出口 IP 防误杀） |
| `max_failures_account` | `5` | 按账号阈值 |
| `lock_sec` / `lock_sec_max` | `900` / `86400` | 基础锁定时长 / 上限（重复触发指数升级 ×2） |
| `firewall` | `auto` | 系统层封锁驱动：`off` / `auto`（自动识别）/ `ufw` / `iptables` / `firewall-cmd`；IP 锁定时下发 DROP 规则、TTL 到期自动解封；容器内/无权限自动降级为网关层软锁 |
| `notify_url` / `notify_secret` | 空 | 登录失败 / 账号锁定事件 HTTP 异步告警（POST JSON + `X-Glacier-Signature` HMAC 签名、退避重试） |
| `auth_plugin`（auth 段） | `mysql_native_password` | 握手默认登录算法：`mysql_native_password` / `caching_sha2_password` / `sha256_password`；账号级可用 `CREATE USER … IDENTIFIED WITH <plugin>` 覆盖。caching_sha2/sha256 非 TLS 密码交换用 RSA 密钥 `<db_dir>/glacier_rsa.pem`（首启自动生成，随数据目录备份） |

锁定持久化于 `glacier_auth.db`（**重启不解除**）；被锁账号/IP 登录返回 3119；
**本机回环地址（127.x.x.x / ::1 / localhost）永不锁定**——本机客户端密码配错不会把
127.0.0.1 锁死在管理面之外（审计照记，账号维度计数不受影响）。
解锁途径：管理面 `SHOW LOGIN ATTEMPTS [LIMIT n]` / `SHOW LOCKED` / `UNLOCK ACCOUNT u` /
`UNLOCK IP x.x.x.x` / `UNLOCK ALL`；账号被锁无法登录管理面时用**命令行旁路解锁**
`glaciertdb -db-dir <dir> -unlock-user <账号>` / `-unlock-ip <IP>` / `-show-locks`
（服务运行中可用，不抢目录锁）。

### 2.9a rollup 多粒度预聚合（rollup）

时序 `points(series_id, ts, val)` 表写入同遍落 `points_m1/h1/d1` 汇总表，长范围聚合查询自动路由
最粗可用粒度（精确等价；详见 docs/时序数据库.md）。

| 项 | 默认 | 说明 |
| --- | --- | --- |
| `rollup.disable` | `false` | true = 关闭自动汇总触发器与查询路由 |

⚠️ 对既有数据首次启用（或中途关闭过）请执行一次 `REBUILD ROLLUP <db>` 补齐历史，否则路由可能漏算触发器建立前的数据。

### 2.9b 键值/队列与端口复用（kv / mux_sniff_ms）

`mode:redis` 同端口 RESP 服务（详见 docs/键值队列.md）。

| 项 | 默认 | 说明 |
| --- | --- | --- |
| `kv.enable` | `true` | RESP 服务开关；false 时 3309 为纯 MySQL（嗅探关闭、连接零延迟） |
| `kv.max_memory_mb` | `0` | 内存上限（0 = 不限）；超限按 eviction 处理 |
| `kv.eviction` | `allkeys-lru` | `allkeys-lru` / `volatile-lru` / `noeviction` |
| `kv.scan_interval_sec` | `5` | TTL 主动扫描周期（最低 1） |
| `mux_sniff_ms` | `300` | 3309 端口复用嗅探窗口：等待客户端首包识别 mode:/RESP/AMQP，超时按 MySQL；高 RTT 客户端调大，纯 MySQL 场景设 `kv.enable: false` |

管理面热改：`SET KV MAX_MEMORY <mb>` / `SET KV EVICTION <policy>`；统计 `SHOW KV STATS` / `SELECT * FROM kv_stats`。

### 2.9c 消息队列（mq）

`mode:rabbitmq` 同端口 AMQP 0-9-1 基本队列（详见 docs/消息队列.md）。

| 项 | 默认 | 说明 |
| --- | --- | --- |
| `mq.enable` | `true` | AMQP 服务开关；false 时 3309 不识别 AMQP（嗅探跳过） |
| `mq.max_message_mb` | `32` | 单条消息上限 |

### 2.9d MySQL 协议服务（mysql）

3309 复用端口上的 MySQL 协议面开关。

| 项 | 默认 | 说明 |
| --- | --- | --- |
| `mysql.enable` | `true` | `false` 时 3309 不再服务 MySQL（MySQL 客户端连接即断开；RESP/AMQP/MQTT 不受影响）；与 `kv.enable` / `mq.enable` 同时关闭时**不监听 3309**，进程保持运行（适合纯 S3 等独立端口部署） |

### 2.10 S3 对象存储（s3）

可选模块（`enable: true` 开启），AWS Signature V4 兼容的对象存储，独立 HTTP(S) 监听器，
详见 [S3对象存储.md](S3对象存储.md)。

| 项 | 默认 | 说明 |
| --- | --- | --- |
| `enable` | `false` | 模块开关；关闭时不监听、管理 SQL 报 1105 |
| `region` | `*` | `'*'` / 空 = 客户端签名任意 region 或不传均可；具体值 = 签名 scope 必须一致 |

| `default_owner` | `glacier` | `CREATE BUCKET` / `CREATE S3 KEY` 未指定属主时的默认用户 |

| `bucket_limits` | `{}` | 按桶覆盖（非 0 字段生效） |
| `lifecycle_interval_sec` | `3600` | 生命周期规则扫描周期（最低 60） |
| `callback_secret` | 空 | 上传回调默认 HMAC 签名密钥（桶级 `SET S3 CALLBACK ... SECRET` 覆盖） |

## 3. 命令行参数

优先级高于配置文件。

| 参数 | 说明 |
| --- | --- |
| `-config <path>` | 配置文件路径，默认 `config.yaml`——依次查找 `./config.yaml` → 可执行文件同目录 → `/app/config.yaml`（Docker 惯例），全不存在时用内置默认值 |
| `-db-dir <dir>` | 覆盖库目录 |
| `-db <file.db>` | 兼容旧参数：取目录 = 所在目录、默认库 = 文件名去扩展 |
| `-listen <addr>` | 覆盖监听地址 |
| `-unlock-user <账号>` | CLI 解锁账号：清除自动锁/手动锁/失败计数（**服务运行中旁路可用**，不抢目录锁，WAL 并发安全） |
| `-unlock-ip <IP>` | CLI 解锁 IP：清除自动锁/失败计数/防火墙封锁 |
| `-show-locks` | CLI 查看当前防爆破锁定列表（账号 + IP）；与其他参数组合时先解锁后展示 |
| `-vacuum` / `-vacuum-db <db>` | CLI 离线真空（服务必须停止；与目录锁互斥） |
| `-force-unlock` | db 目录锁被异常占用时强制解锁启动（拒绝抢活进程的锁） |
| `-v` / `--version` | 打印 GlacierTDB 自身版本后退出（非 MySQL 协议版本） |

```bash
./glaciertdb -v
# GlacierTDB 1.3.10.beta (mysql protocol 8.99.999, linux/amd64)

# 账号被防爆破锁死、无法登录管理面时（服务保持运行）：
./glaciertdb -db-dir /data -unlock-user app_writer
./glaciertdb -db-dir /data -unlock-ip 10.1.2.3
./glaciertdb -db-dir /data -show-locks
```

## 5. 常见问题

**Q：改了 `auth.password` 重启后怎么没生效？**
管理面 `SET PASSWORD` 会在 `<db_dir>/glacier.json` 留下持久化密码，它**优先于**配置文件。删除该文件即可回到配置文件密码（`readonly_password` 同理）。

**Q：连接报「db dir 不存在或不是目录」？**
`db_dir` 指向的目录需要**事先创建**且可写（WAL 要在同目录建 `-wal`/`-shm`）；挂载 Docker 卷时挂**目录**，不要挂单个 `.db` 文件。

**Q：`memory_limit_mb=512` 为什么内存还是能超过一点？**
它是 Go 运行时**软**上限（GOMEMLIMIT 语义）：GC 会尽全力回收压回，但不含 SQLite 页缓存之外的少量运行时开销，也不代替 `max_result_rows` 的查询防线。

**Q：并发热改后重启丢了？**
设计如此：`SET GLOBAL_THREADS` 等仅运行时生效，持久值写回 `config.yaml` 的 `concurrency` 段。
