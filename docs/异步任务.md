# GlacierTDB 异步任务手册

> 异步查询与定时任务引擎。
> 适用场景：**超大数据查询**（不受在线查询行数上限与连接超时约束）、**削峰执行**（夜间窗口 / 资源门槛门控）、**周期定时任务**（每日 ETL、对账、报表）。
>
> 登录用户名固定为 `glacier`；提交即秒回 `job_id`，执行、回调、结果拉取全部异步。

---

## 1. 任务类型总览

| 类型 | 触发方式 | 关键参数 | 典型场景 |
| --- | --- | --- | --- |
| **一次性（立即）** | 提交后立即执行 | 无（默认） | 大报表后台跑 |
| **AT 定时** | 指定时刻执行 | `AT '17:00'` / `AT '2026-11-01 02:00:00'` | 凌晨低峰 ETL |
| **每日窗口** | 每日时间区间内执行 | `WINDOW '17:00-20:00'`（支持跨午夜 `'22:00-06:00'`） | 夜间批处理窗口 |
| **周几限定窗口** | 仅限某几天的窗口内执行 | `WINDOW '周五 17:00-20:00'`（周一..周日 / MON..SUN） | 周报、周末批处理 |
| **资源门控** | 指标达标才执行 | `WHEN CPU < 70 AND MEM < 80 …` | 生产高峰避让 |
| **EVERY 周期任务** | 执行完自动重排下一次 | `EVERY DAY [AT '17:00']` / `EVERY 30 MINUTES` | 每日对账、定时采样 |

参数可组合：`AT` + `WHEN`（到点后仍受资源门槛约束）、`WINDOW` + `WHEN`（窗口内等资源）、`EVERY` + `CALLBACK`（周期推送）。

## 2. SUBMIT QUERY 全量语法

```sql
SUBMIT QUERY '<SQL 文本>'
  [CALLBACK '<url>' [SIGN '<secret>']]
  [TIMEOUT <秒>]
  [AT '<HH:MM>' | '<YYYY-MM-DD HH:MM:SS>']
  [WINDOW '[周X ]HH:MM-HH:MM']
  [WHEN <指标> <op> <阈值> [AND <指标> <op> <阈值> …]]
  [PARTITION BY ROWS <n> | PARTITION BY BYTES <n>]
  [EVERY DAY [AT 'HH:MM'] | EVERY WEEK [ON 周X] [AT 'HH:MM'] | EVERY MONTH [ON <1-31>] [AT 'HH:MM'] |
   EVERY YEAR [ON '<MM-DD>'] [AT 'HH:MM'] | EVERY HOUR | EVERY MINUTE | EVERY <n> SECONDS|MINUTES|HOURS|WEEKS|MONTHS|YEARS]
  [RETAIN <n>[s|m|h]];
```

- **`'<SQL 文本>'`**：要执行的 SELECT 语句；串内单引号用 `''` 转义。
- 返回结果集：`job_id`（如 `j_20261020_153000_0001`）与初始 `state`（`PENDING`）。

### 2.1 CALLBACK —— 回调通道

| 写法 | 通道 | 说明 |
| --- | --- | --- |
| `CALLBACK 'http://ops/hook'` | **HTTP POST** | 默认通道；JSON 载荷（见 §5.1）；`2xx` 视为成功 |
| `CALLBACK 'tcp://host:port'` | **TCP 流** | 服务端主动连过去：首行元信息 JSON，随后列头 + 数据 JSONL 流，EOF 结束 |
| `CALLBACK 'amqp://user:pass@host:5672/' [QUEUE q]` | **RabbitMQ** | 发布到队列（默认 `glacier_jobs`），持久化消息 |
| `CALLBACK 'kafka://broker:9092' [TOPIC t]` | **Kafka** | 写入 topic（默认 `glacier_jobs`），key=job_id |

四态一律回调：`DONE` / `ERROR` / `EXPIRED` / `CANCELLED`。不带 CALLBACK 的任务即纯后台任务 / 定时任务，用 SQL 拉取结果。

### 2.2 SIGN —— HMAC 签名

指定 `SIGN '<secret>'` 后每个回调请求携带请求头：

```
X-Glacier-Signature: sha256=HMAC-SHA256(secret, body)
X-Glacier-Job: <job_id>
```

接收端用同样密钥对原始 body 计算 HMAC 比对即可防伪造。分片回调的每一片独立签名。

### 2.3 TIMEOUT / RETAIN

- `TIMEOUT <秒>`：任务**未开始执行**前的等待时限（默认 `async_query.default_timeout_sec` = 1800）；
  等待 AT/WINDOW/WHEN 期间超时 → `EXPIRED`。
- `RETAIN <n>[s|m|h]`：结果保留时长，覆盖全局 `async_query.result_retain_sec`（默认 **60 秒**），
  到期结果文件自动删除、任务转 `EXPIRED`；大结果建议显式给足（如 `RETAIN 2h`）。

### 2.4 AT —— 指定时刻

- `AT '17:00'`：今日 17:00（已过则明日）；`AT '2026-11-01 02:00:00'`：绝对时刻（也接受 `YYYY-MM-DD`）。
- 到点后若还有 `WHEN` 门槛，继续等资源；超时仍 `EXPIRED`。

### 2.5 WINDOW —— 每日 / 周几窗口

- 双边区间 `[起, 止)`：`WINDOW '17:00-20:00'` = 17 点后、20 点前；支持跨午夜 `WINDOW '22:00-06:00'`；
- **窗口结束仍未执行 → 当日 EXPIRED，不跨天滚动**（防止"明天的查询"意外执行）；
- 周几限定：`WINDOW '周五 17:00-20:00'` / `WINDOW 'FRI 17:00-20:00'`——仅在指定 weekday 的窗口内可执行，
  其他天持续等待（由 `TIMEOUT` 兜底）；`query_jobs.window` 列显示 `周五 17:00-20:00`；
- 需要每日调度的显式用 `EVERY DAY`（见 2.7）。

### 2.6 WHEN —— 资源门槛

指标由后台采样器周期采集（`async_query.metrics_interval_sec`，默认 30s，最低 10s），提交路径零开销：

| 指标 | 含义 | 层级 |
| --- | --- | --- |
| `CPU` | 服务器整机 CPU 占用 % | 服务器级（/proc/stat） |
| `MEM` | 服务器内存**已用** % | 服务器级（/proc/meminfo） |
| `DISK_MBPS` | 服务器整机磁盘写速率 MB/s（物理盘合计） | 服务器级（/proc/diskstats） |
| `APP_CPU` | 本网关进程 CPU % | 应用级（/proc/self/stat） |
| `APP_MEM` | 本网关进程 RSS / 总内存 % | 应用级（/proc/self/status） |
| `IO_MBPS` | 本网关进程写盘速率 MB/s | 应用级（/proc/self/io） |

- 操作符 `<  <=  >  >=`；多条件 **AND** 组合；
- 解析不了的条件 / 未知指标一律视为**不满足**（保守：宁可等待也不超载执行）；
- 当前值可用 **`SHOW QUERY VARS`** 查看（见 §4：Variable_name / Value / Level / Description 四列；值 NULL = 首采只建基线）；
- `DISK_MBPS` 为物理盘（sd/vd/xvd/hd/nvme/mmcblk，分区不计）sectors written 增量折算；容器内 `/proc/diskstats` 为宿主机视图，反映整机；
- 采样器基于 Linux `/proc`；非 Linux 宿主上指标缺失时 `WHEN` 任务不会执行，请勿在该环境使用。

### 2.7 EVERY —— 周期任务

| 写法 | 语义 |
| --- | --- |
| `EVERY DAY` | 每日一次（上一次执行完 24h 后） |
| `EVERY DAY AT '17:00'` | 每日固定 17:00（错过当日时刻则顺延次日） |
| `EVERY WEEK [ON 周五] [AT '02:00']` | **每周调度**：缺省周几 = 提交日；首次执行自动排到下一周期时刻 |
| `EVERY 2 WEEKS ON 周一 AT '03:00'` | **每 N 周**：`ON` 接受 `周一..周日 / MON..SUN` |
| `EVERY MONTH [ON 15] [AT '03:00']` | **每月调度**：`ON` 为日号 1-31，缺省 = 提交日；月尾日 clamp（1/31 → 2/28） |
| `EVERY 3 MONTHS ON 31 AT '01:30'` | **每 N 月**：同上，按日历月间隔跳 |
| `EVERY YEAR [ON '03-01'] [AT '02:00']` | **每年调度**：`ON` 为 `MM-DD`，缺省 = 提交日的月日；2/29 平年 clamp 到 2/28 |
| `EVERY 2 YEARS ON '12-31' AT '23:00'` | **每 N 年** |
| `EVERY HOUR` / `EVERY MINUTE` / `EVERY SECOND` | 固定周期 |
| `EVERY 30 MINUTES` / `EVERY 6 HOURS` / `EVERY 90 SECONDS` | n 倍周期 |

- 执行完**自动重排下一次**（同一 `recur_group` 链）；`CANCEL QUERY` 取消整条链（即使链头已 DONE 也可停链）；
- **链级启停**：`PAUSE QUERY '<job_id>'` 挂起排期（冻结 TIMEOUT 倒计时、不丢链），
  `RESUME QUERY '<job_id>'` 恢复；
- **周期配置查询**：`SHOW QUERY SCHEDULE` / `SELECT * FROM query_schedule`——
  每链一行（`recur_group / job_id / sql / schedule / window / when / next_run / last_run / last_state / paused`），
  `schedule` 为人类可读表达（`EVERY WEEK ON 周五 AT 02:00`）；`query_jobs.schedule` / `query_jobs.qos_wait_ms`
  为逐任务列；
- 无 CALLBACK 的 EVERY 任务 = 传统定时任务（结果照常落盘可拉取）。

### 2.8 PARTITION —— 分片回调

海量结果分多片推送，**仅 HTTP 通道**：

```sql
SUBMIT QUERY 'SELECT id, v FROM big_table'
  CALLBACK 'http://ops/hook' SIGN 's3cret'
  PARTITION BY ROWS 50000 RETAIN 2h;     -- 每 5 万行一片
-- 或 PARTITION BY BYTES 8388608        -- 每片约 8MB（按行序列化字节数累计切分）
```

流程：先 POST 一次任务级元信息（含 `parts`、`partition_rows` / `partition_bytes`），随后逐片独立 POST（片号 1..parts）：

```json
{ "job_id": "j_x", "part": 3, "parts": 12, "rows": 50000,
  "columns": ["id", "v"], "data": [[1, "a"], [2, "b"]], "data_encoding": "json" }
```

- 单片负载超过 `async_query.callback_max_inline_kb`（默认 64KB）时省略 `data`，附 `fetch` 字段给出
  等价 SQL 拉取凭证（`FETCH QUERY RESULT 'j_x' LIMIT n OFFSET m`）；
- 每片独立重试（0/1/5/15s 退避），失败不阻塞后续片。

## 3. 生命周期

```
PENDING ──(AT 到点/窗口内/资源达标)──► RUNNING ──► DONE
   │                                   │
   │ 等待中：WAIT_TIME（AT/WINDOW 未到）│ 执行出错
   │         WAIT_RESOURCE（WHEN 未达标）▼
   ├──► CANCELLED（CANCEL QUERY）     ERROR
   ├──► EXPIRED（窗口结束未执行 / TIMEOUT / 结果过期清理）
```

- `query_jobs.state` 可能值：`PENDING / RUNNING / DONE / ERROR / CANCELLED / EXPIRED`；
- `SCRIPT` / `OUTPUT` 选项语法已预留（见 CHANGELOG），当前提交会接受参数但不会执行管道。

## 4. 结果拉取与管理

```sql
SHOW QUERY JOBS;                                   -- 全部任务（新→旧）
SELECT job_id, state, rows, elapsed_ms FROM query_jobs WHERE state = 'DONE';
SELECT job_id, window, when FROM query_jobs WHERE recur_group != '';

FETCH QUERY RESULT 'j_xxx' LIMIT 1000 OFFSET 5000; -- 分页拉取结果（默认 LIMIT 1000）
SELECT * FROM query_result('j_xxx') LIMIT 100;     -- 表函数等价形式

SHOW QUERY VARS;                                   -- WHEN 监测变量当前值
SHOW QUERY SCHEDULE;                               -- 周期配置查询
PAUSE QUERY 'j_xxx'; RESUME QUERY 'j_xxx';         -- 周期链挂起/恢复

CANCEL QUERY 'j_xxx';     -- 取消（周期链取消整链）
DROP QUERY RESULT 'j_xxx'; -- 立即删除结果文件
```

`SHOW QUERY VARS` 返回 `Variable_name / Value / Level / Description` 四列（§2.6 指标表，
含服务器级 `DISK_MBPS`）；`Value` 为 NULL 表示首采只建基线尚无差值；只读账号可执行
（查看类命令），`SUBMIT / CANCEL / DROP` 对只读账号返回 `1290`。

`query_jobs` 列（16 列）：

| 列 | 说明 |
| --- | --- |
| `job_id` / `state` / `sql` / `submit_ts` | ID、状态、原文、提交时间 |
| `elapsed_ms` / `rows` / `bytes` / `error` | 执行耗时、结果行数/字节数、错误信息 |
| `callback_url` / `at` / `window` / `when` | 回调地址、计划时刻（周期任务显示 `daily HH:MM`）、窗口（含周几前缀）、资源门槛 |
| `every_sec` / `recur_group` | 周期秒数、周期链 ID |
| `partition_rows` / `partition_bytes` | 分片大小（未设置时为 0/NULL） |
| `qos_wait_ms` / `schedule` | QoS 排队毫秒、人类可读周期表达） |

支持 `WHERE col = 'v' / col LIKE 'p' / col IN (...)` AND 组合过滤与列投影。

## 5. 回调协议

### 5.1 HTTP POST 载荷（任务级元信息）

```json
{
  "job_id": "j_20261020_153000_0001",
  "state": "DONE",
  "rows": 123456,
  "bytes": 9876543,
  "elapsed_ms": 45230,
  "expires_ts": "2026-10-20 16:00:00"
}
```

失败任务附 `"error": "..."`；分片任务附 `"parts"` / `"partition_rows"`。

- 成功判定：HTTP `2xx`；失败退避重试 4 次（0s/1s/5s/15s）；
- `Content-Type: application/json`；签名头见 §2.2。

### 5.2 TCP 流协议

网关主动连接 `tcp://host:port`：第 1 行任务元信息 JSON，第 2 行列头 JSON（`{"columns":[…]}`），
随后每行一个数据 JSON 数组，连接关闭（EOF）表示结束。

### 5.3 AMQP / Kafka

消息体与 §5.1 相同；RabbitMQ 持久化写入队列（默认 `glacier_jobs`），Kafka 以 job_id 为 key 写 topic（默认 `glacier_jobs`）。
网关编译产物已内置两协议客户端；无法连通时任务仍正常完成，仅记录回调失败日志。

## 6. 配置项（config.yaml）

```yaml
async_query:
  enable: true                  # 段缺失时默认启用
  workers: 2                    # 结果落盘/回调并发 worker 提示值
  metrics_interval_sec: 30      # WHEN 资源采样周期（最低 10，低于 10 启动时按 10 处理）
  result_retain_sec: 60         # 结果默认保留秒数（RETAIN 可按任务覆盖）
  default_timeout_sec: 1800     # 默认等待超时（TIMEOUT 可覆盖）
  jobs_dir: ""                  # 结果目录（默认 <db_dir>/jobs）
  callback_max_inline_kb: 64    # 分片回调单片数据内联上限，超限改发拉取凭证
  nodejs_path: ""               # SCRIPT 后处理 runtime（.js；空 = 禁用该类脚本）
  python_path: ""               # SCRIPT 后处理 runtime（.py；空 = 禁用）
  php_path: ""                  # SCRIPT 后处理 runtime（.php；空 = 禁用）
  script_dir: ""                # SCRIPT 白名单目录（脚本必须位于其下）
```

任务结果文件：`<jobs_dir>/<job_id>.jsonl`（首行列头，随后逐行数据）。

## 7. 示例

```sql
-- ① 夜间窗口跑大报表，完了推送运营系统（签名 + 分片）
SUBMIT QUERY 'SELECT series_id, count(*), avg(val) FROM points GROUP BY series_id'
  CALLBACK 'http://ops.internal/report' SIGN 'hush-hush'
  WINDOW '23:00-06:00' TIMEOUT 36000 PARTITION BY ROWS 50000 RETAIN 6h;

-- ② 资源门控：CPU 空了才回填 uuid（配合 API 侧 MD5 探测）
SUBMIT QUERY 'UPDATE camera SET uuid = MD5(CONCAT(id, ip)) WHERE uuid = '''''
  WHEN CPU < 30 AND APP_CPU < 50 TIMEOUT 86400;

-- ③ 每日 02:10 对账，TCP 流推给本机采集端
SUBMIT QUERY 'SELECT … FROM ledger WHERE dt = date(''now'')'
  CALLBACK 'tcp://10.25.20.16:18888' EVERY DAY AT '02:10';

-- ④ 周五盘后周报
SUBMIT QUERY 'SELECT …' CALLBACK 'http://ops/weekly' WINDOW '周五 18:00-23:00';

-- ⑤ 拉取与清理
FETCH QUERY RESULT 'j_20261020_153000_0001' LIMIT 10000;
DROP QUERY RESULT 'j_20261020_153000_0001';
```

## 8. 边界与注意事项

- 异步 worker 与在线查询共享 `global_threads` 闸门，不会挤占在线流量配额之外再另开并发；
- 结果行数不受在线 `sqlite.max_result_rows` 限制（落盘流式），但受磁盘空间与 `jobs_dir_max_gb` 约束；
- 提交的 SQL 在**默认库**（`async` 会话连 `default_db`）上执行，跨库请在 SQL 内显式 ATTACH（当前禁止）或切默认库；
- `CANCEL` 对执行中任务设置中断标记，聚合查询在下一次内层批次感知后停止；
- 重启后任务队列不持久化（内存态）：PENDING 任务丢失、已完成结果文件仍在 `jobs_dir` 可拉取（TTL 独立计算）。

## SCRIPT 后处理管道

`SUBMIT QUERY '<sql>' SCRIPT '<脚本>' [OUTPUT <名>]` —— 查询结果 JSONL（`jobs/<id>.jsonl`，首行
columns、随后每行一条记录）经 **stdin** 流入脚本，脚本 **stdout** 产物落 `jobs/<id>.<OUTPUT>`
（缺省 OUTPUT=out）：

| 项 | 说明 |
| --- | --- |
| 运行时 | 按扩展名选择：`.js` → `async_query.nodejs_path`，`.py` → `async_query.python_path`，`.php` → `async_query.php_path`（空 = 禁用该类脚本，任务 ERROR 提示 `script runtime disabled`） |
| 白名单 | 脚本必须位于 `async_query.script_dir` 目录内（相对路径以该目录为根；越界拒绝，防任意路径执行） |
| 超时/取消 | 任务 `TIMEOUT` 到期中断；`CANCEL QUERY` 可杀；stderr 摘要（300 字符）进错误消息 |
| 状态机 | 执行期间任务状态为 `SCRIPT`，完成后 `DONE`；产物大小计入 `bytes` |

示例（nodejs 侧）：

```js
// scripts/pipe.js：统计行数并输出
let n = 0; let head = '';
process.stdin.on('data', d => { head += d; });
process.stdin.on('end', () => {
  const lines = head.trim().split('
');
  console.log(JSON.stringify({ header: JSON.parse(lines[0]), rows: lines.length - 1 }));
});
```

```sql
SUBMIT QUERY 'SELECT * FROM points LIMIT 1000' SCRIPT 'pipe.js' OUTPUT summary;
-- 产物：jobs/<job_id>.summary
```
