# GlacierTDB 时序冷库设计

> GlacierTDB 时序能力手册：存储模型、查询改写、实测结果与路线图。
> 定位：热数据留在独立部署的 MySQL，本库专注**冷查询 / 历史归档**。
> 主轴三件套：**时间有序存储、rollup 预聚合、冷压缩**——全部落在 SQLite 与网关改写层的能力圆内，零新中间件。

---

## 1. 存储：series 维表 + 时间聚簇

标准建表脚本见 [`schema/timeseries.sql`](../schema/timeseries.sql)（可经 mysql 客户端直接执行）：

```sql
-- series 维表 = InfluxDB 的 series key（measurement + tagset）
CREATE TABLE series (
  id   INTEGER PRIMARY KEY,
  meas TEXT NOT NULL,
  tags TEXT NOT NULL,            -- JSON: {"host":"a1","region":"bj"}
  UNIQUE(meas, tags)
);

-- 事实表：(series_id, ts) 聚簇主键 = 时间有序存储，
-- 同一序列物理相邻、时间递增，范围扫描即顺序 IO
CREATE TABLE points (
  series_id INTEGER NOT NULL,
  ts        INTEGER NOT NULL,    -- epoch ms（全网关时序改写的前提约定）
  val       REAL,
  PRIMARY KEY (series_id, ts)
) WITHOUT ROWID;

-- 常用 tag 过滤 = 表达式索引（单个 tag 的"倒排"）
CREATE INDEX idx_series_host ON series(json_extract(tags, '$.host'));

-- 纯时间范围跨序列查询建议建 ts 二级索引（聚簇主键最左列是 series_id，
-- 不建此索引时纯 ts 谓词会全表扫；按查询模式决定是否需要）
CREATE INDEX idx_points_ts ON points(ts);
```

回填 ETL 规范：按 series + ts 排序、大事务批量插入（如每 10 万点一个事务）。

## 2. 查询：网关改写层

客户端保持**纯 MySQL 写法**，网关自动改写为 SQLite 等价形式：

| MySQL 写法 | 自动改写为 | 说明 |
| --- | --- | --- |
| `ts >= NOW() - INTERVAL 1 HOUR` | `ts >= (strftime('%s','now')*1000-3600000)` | 时间谓词整数化，命中聚簇索引 |
| `ts >= '2026-10-01 00:00:00'` | `ts >= strftime('%s','2026-10-01 00:00:00')*1000` | 日期字符串整数化（按 UTC 解析），避免 INTEGER 列与 TEXT 字面量比较静默恒真/恒假 |
| `GROUP BY time(3600000)` | `GROUP BY (ts/3600000*3600000)` | InfluxDB 风格整数分桶（桶宽单位毫秒） |
| `SELECT time(3600000), …` | `SELECT (ts/3600000*3600000), …` | SELECT 与 GROUP BY 两处同步改写 |
| `SELECT FROM_UNIXTIME(ts/1000)` | `datetime(ts/1000,'unixepoch')` | 秒级时间戳转可读时间 |
| `SELECT LAST_INSERT_ID()` | `last_insert_rowid()` | 自增回读 |

`INTERVAL` 支持的单位：`SECOND / MINUTE / HOUR / DAY / WEEK / MONTH(=30天) / YEAR(=365天)`（近似，冷查询场景足够）。

典型查询：

```sql
-- 最近 1 小时均值（自动整数化，命中 (series_id, ts) 聚簇主键）
SELECT avg(val) FROM points
WHERE series_id = 1 AND ts >= NOW() - INTERVAL 1 HOUR;

-- 小时桶聚合（InfluxDB 风格）
SELECT time(3600000), min(val), max(val), avg(val), count(*)
FROM points
WHERE series_id = 1
  AND ts >= NOW() - INTERVAL 6 HOUR AND ts < NOW() - INTERVAL 1 HOUR
GROUP BY time(3600000)
ORDER BY 1;

-- tag 过滤（表达式索引）+ 日期字符串谓词
SELECT p.ts, p.val FROM points p
JOIN series s ON s.id = p.series_id
WHERE json_extract(s.tags, '$.host') = 'a1'
  AND p.ts >= '2026-10-01 00:00:00';

-- 执行计划检查（EXPLAIN QUERY PLAN 原样透传）
EXPLAIN QUERY PLAN
SELECT series_id, count(*) FROM points
WHERE series_id = 1 AND ts >= 1791900000000 AND ts < 1791903600000
GROUP BY series_id;
-- → SEARCH points USING PRIMARY KEY (series_id=? AND ts>? AND ts<?)
```

### 实测结果（tests/test_timeseries.py，11 项全过）

- 3 序列 × 2880 分钟 = **8640 点**回填；
- `NOW() - INTERVAL 1 HOUR` 改写与直接数字比较**结果等价**（均 60 点）；
- 日期字符串谓词整数化正确（与 epoch 毫秒数字比较一致）；
- 6h−1h 非整点窗口 → 6 个整点桶，满桶 60 点、窗口合计 300 点，桶起始值全部对齐整点；
- `EXPLAIN QUERY PLAN`：范围查询命中 `(series_id, ts)` 聚簇主键；建 `ts` 二级索引后纯时间谓词走 `COVERING INDEX`，无全表扫。

## 3. 压缩与固化

- **模型**：`points`（series_id/ts/val 约定）按时间步长（默认 1 天）分块，完全早于边界的块
  gzip 固化进 `points_cold(chunk, series_id, rows, min_ts, max_ts, algo, zdata)`——
  编码为 varint(ts 增量) + 值原码（float64 位 / 文本 / NULL 标记），**字节级无损**，实测压缩比 ≈ 3.8；
- **命令**：`COMPRESS COLD points BEFORE <整数ms | 'YYYY-MM-DD[ HH:MM:SS]' | NOW()-INTERVAL n UNIT> [STEP n DAY|HOUR]`、
  `THAW COLD points [ALL|BEFORE t|CHUNK ms]`、`SHOW COLD [points]`；
- **透明性**：读查询解析 ts 谓词——触及冻结区间先自动解冻（无谓词保守全解）；写入撞冻结区间
  PK 冲突自动全解重试一次；解冻期间临时摘除 rollup 触发器，`points_m1` 的 `SUM(cnt)` 与全量严格一致；
- **自动策略**：`timeseries.cold_after_days > 0` 后台周期固化全部库（`cold_scan_min_sec` 扫描周期）；
- 事务内显式事务中 COMPRESS/THAW 拒绝（1192）；显式事务中的查询跳过自动解冻（只读热数据）。

## 4. 与 InfluxDB 的差异（诚实声明）

| 维度 | GlacierTDB |
| --- | --- |
| ✅ 对齐 | 时间范围查询延迟、长范围聚合（rollup 预聚合）、tag 过滤、分区管理、**多核并行**（聚合/GROUP BY 分片/明细导出三形态） |
| ⚠️ 低于 | 原生压缩比（由 Gorilla chunk 压缩路线补齐）；无原生空间索引 |
| ✅ 反超 | **标准 SQL 全量能力**（JOIN / 窗口函数 / CTE 随便用）、一个文件拷走就是备份、零中间件、信创无障碍 |

---

## 5. 明确不做（防范围蔓延）

- ✗ DuckDB / CGO 加速——破坏纯 Go 单二进制与信创交叉编译；
- ✗ 冷热透明路由（网关转发 MySQL）——引入对 MySQL 存活的依赖，违背零中间件；
- ✗ InfluxQL / Flux 全量兼容——保持 MySQL 方言本身就是卖点；
- ✗ 多写者 / 写扩展——冷库只有一次性回填；
- ✗ 后台常驻批处理聚合——rollup 为**写入触发式**（INSERT 触发器同遍落汇总表），无守护进程、无调度任务。

## rollup 多粒度预聚合

InfluxDB 长范围查询快的本质是预聚合。GlacierTDB 在标准时序 schema（`points(series_id, ts, val)`）上提供：

**写入同遍落**：首次写 `points` 时自动创建三张汇总表与 AFTER INSERT 触发器——
`points_m1` / `points_h1` / `points_d1`（1 分钟 / 1 小时 / 1 天桶），每行
`(series_id, bucket_ts, cnt, cntv, sum_val, min_val, max_val)`，随 INSERT 实时累加。

**查询自动路由**：带时间范围的聚合查询自动改走「汇总表满桶 + 原始表边缘桶」UNION，
选取可用的最粗粒度（桶宽整除 GROUP BY 桶宽、范围内至少一个满桶）：

```sql
-- 自动路由到 points_h1（或更粗），结果与全量扫 points 精确一致
SELECT avg(val) FROM points WHERE ts >= 1760000000000 AND ts <= 1760172000000;
SELECT series_id, time(3600000), avg(val) FROM points
  WHERE ts >= 1760000000000 AND ts <= 1760172000000 GROUP BY series_id, time(3600000);
```

- 仅支持标准 schema 与可合并聚合（COUNT/SUM/MIN/MAX/AVG）；谓词限 `ts` 范围 + `series_id` 过滤
 （对 `val` 过滤等无法下推的形态自动回退全量扫）；
- **边缘桶回退原始行**，无近似误差；非对齐时间范围同样精确；
- 存量数据回填：`REBUILD ROLLUP <db>;`（超级用户；启用 rollup 前的历史数据必须执行一次）；
- 关闭：`rollup.disable: true`。

> 无 GROUP BY 的全范围聚合、含 val 谓词、或范围不足一个满桶时走原始表——语义永远优先于速度。

## v1.3.11：时序大表谓词 + ts 秒/毫秒/微秒自动换算

### 建表谓词（特殊谓词声明）

```sql
CREATE TABLE metrics (
  series_id INTEGER, ts INTEGER, val REAL, PRIMARY KEY(series_id, ts)
) WITH (TIMESERIES, TS_UNIT='s', TS_COLUMN='ts');
```

声明后该表即**时序大表**，享受全套时序优化红利（不再固定 points 表名）：

- 冷压缩 / 自动解冻 / 约束解冻（`COMPRESS COLD metrics BEFORE ...`、`SHOW COLD`）；
- rollup 预聚合与聚合路由（`<tbl>_m1/h1/d1` + 触发器按表懒建）；
- 后台 `timeseries.cold_after_days` 策略覆盖全部声明表；
- `SHOW TS TABLES [ON <db>]` 列声明；`REBUILD ROLLUP <db>.<tbl>` 按表回填。

声明落在库内 sidecar 表 `__glacier_tsmeta`（随库迁移 / 备份）。`points` 表保持隐式
声明（ms 精度），存量行为完全兼容。

### ts 三精度与查询自动换算

`TS_UNIT` 支持 `s`（秒）/ `ms`（毫秒，默认）/ `us`（微秒）。查询谓词按**数值量纲自动
检测并换算**到存储精度：

| 字面量量级 | 判定 |
| --- | --- |
| ≥ 1e14 | 微秒 |
| ≥ 1e11 | 毫秒 |
| ≥ 1e9 | 秒 |
| 其余 | 不转换（按存储精度原样比较） |

- **存秒查毫秒**：`WHERE ts >= 1770000000000`（13 位毫秒）自动 ÷1000 命中秒存储；
- **存毫秒查秒**：10 位秒字面量自动 ×1000；
- **日期串**：`WHERE ts >= '2026-10-27'`（UTC）自动转存储精度整数（整数列与文本比较
  本无意义，转换后语义正确）；
- **桶宽**：`GROUP BY ts/60000*60000` / `time(60000)` 的 N 按毫秒惯例自动换算到存储精度；
- 换算仅当语句提及声明表时发生；多表混提且精度不一致时保守不改写。
- 边界同理：`COMPRESS/THAW COLD ... BEFORE <n>` 的边界与 STEP 按声明精度换算。
